# Недостоверная занятость тома

## Цель

FTP-том в секции «Диски» всегда показан красной полоской на всю ширину с
подписью «Свободно 0 Б из 1,0 ГБ». Это не состояние сервера, а заглушка
драйвера: macOS монтирует FTP через NFS-мост и отдаёт синтетические числа.

```
ftp://u3371448@31.31.196.75   1048576  1048576  0  100%
```

`statvfs` подтверждает выдумку: `f_blocks = 262144` блоков по 4 КБ — ровно
1 ГБ, `f_bfree = 0`, `f_files = 0`. Ни одна из трёх цифр к серверу отношения
не имеет.

Дальше код работает ровно как написан: `fraction` = 1.0 → `isNearlyFull` =
true → красная полоска. Существующая защита в `VolumeUsage.fraction` ловит
только нулевой `totalBytes`, а здесь он ненулевой и правдоподобный.

Цель — **отличать тома, у которых занятость недостоверна, и не показывать по
ним чисел вовсе**. Настоящее свободное место на FTP не считается: в RFC 959
команды для этого нет, расширения (`SITE DF`, `AVBL`, `XQUOTA`) поддерживает
меньшинство серверов, а macOS монтирует FTP только для чтения — писать туда
всё равно нельзя, и цифра ничему не служит.

Постоянная ложная тревога хуже отсутствия числа: красный, горящий всегда,
перестаёт значить «место кончается».

## Архитектура

### Признак недостоверности — `f_files == 0`

`Sources/PathwayCore/VolumeUsage.swift`

Ноль инод — маркер синтетической файловой системы. У живых томов оно всегда
ненулевое, потому что каталог верхнего уровня сам занимает иноду:

| том | `f_files` | |
|---|---|---|
| `/` | 458 725 | достоверно |
| `/Volumes/Проводник` | 29 | достоверно |
| FTP-том | 0 | синтетика |

Отвергнуто «сетевой том со свободным нулём»: не требует `statfs`, но гасит
полоску и у настоящего сетевого диска, забитого под ноль, — то есть ровно в
тот момент, ради которого полоска и заведена.

Отвергнуто сравнение `totalBytes` с круглым 1 ГБ: совпадение случайно и
сломается при смене заглушки в очередной macOS.

### `VolumeUsage.hasReliableUsage`

Новое хранимое свойство структуры (не вычисляемое: признак приходит от
системы, вывести его из уже имеющихся полей нельзя).

Инициализатор получает его **с умолчанием `true`**. Существующие вызовы —
все тесты и обе точки создания — компилируются без правки, а недостоверность
остаётся тем, что нужно объявить явно.

Производные меняются на нём же:

- `fraction` → 0 при недостоверных числах. Не ради полоски (её ширина в этом
  случае задаётся вью), а чтобы никакой будущий читатель `fraction` не принял
  заглушечную единицу за правду.
- `isNearlyFull` → false. Тревога о конце места на томе, объём которого
  неизвестен, — ложная по определению.
- `caption` → «Объём неизвестен» вместо «Свободно X из Y».

### `VolumeUsageReader` — чтение `f_files`

`URLResourceKey` числа инод не отдаёт вовсе, поэтому нужен прямой `statfs(2)`
по пути тома. Вызов добавляется в `read()` рядом с уже читаемыми ключами.

`statfs` — не новая граница с ОС в смысле правила проекта: `VolumeUsageReading`
уже протокол, подмена в тестах идёт через него, и отдельного протокола ради
одного системного вызова не заводится.

Неудача `statfs` (том отвалился между перечислением и опросом) считается
достоверностью: строка тогда рисуется как раньше. Обратное решение погасило бы
полоски у всех дисков на ровном месте при первой же гонке.

### Вью: серая полоска на всю ширину

`Sources/Pathway/SidebarView.swift`, `VolumeRow`

- Заливка полоски: серый (`Color.secondary.opacity(…)`) вместо
  акцентного/красного, ширина — полная.
- Подпись берётся из `caption`, менять вью под неё не нужно.

Полоска остаётся, а не убирается: у секции «Диски» ровный шаг строк, и строка
без полоски стала бы ниже остальных.

## Поток данных

```
VolumeUsageReader.read()
  └ mountedVolumeURLs + resourceValues → объём, имя, сетевой ли
  └ statfs(path) → f_files
       └ f_files == 0 → hasReliableUsage = false
  ↓
VolumeUsage
  └ fraction → 0, isNearlyFull → false, caption → «Объём неизвестен»
  ↓
VolumesModel.volumes (refresh раз в 30 с)
  ↓
VolumeRow → серая полоска на всю ширину + «Объём неизвестен · логин»
```

## Тесты

`Tests/PathwayCoreTests/VolumeUsageTests.swift`, сьют «Занятость тома»:

- **недостоверная занятость не считается почти заполненной** — том с числами
  FTP-заглушки (1 ГБ общего, 0 свободного, `hasReliableUsage: false`) даёт
  `isNearlyFull == false`. Фиксирует исходную жалобу.
- **недостоверная занятость даёт долю 0, а не единицу** — тот же том,
  `fraction == 0`.
- **подпись недостоверного тома не называет чисел** — `caption` равен «Объём
  неизвестен»; проверяется и отсутствие «1,0 ГБ» в тексте.
- **достоверный том с теми же числами остаётся почти заполненным** — контраст:
  `hasReliableUsage: true`, 1 ГБ общего, 0 свободного → `isNearlyFull == true`.
  Без него легко погасить тревогу для всех.
- **занятость по умолчанию считается достоверной** — инициализатор без
  аргумента даёт `hasReliableUsage == true`.

Чтение `f_files` из `statfs` тестом не покрывается: это опрос конкретной
машины, а `VolumeUsageReading` подменяется целиком — ровно та граница, ради
которой протокол и заведён.

## Ручной чек-лист

- [ ] FTP-том в сайдбаре: полоска серая на всю ширину, подпись «Объём
      неизвестен», логин на месте.
- [ ] Загрузочный том: полоска акцентная, подпись «Свободно X из Y» — как
      раньше.
- [ ] Внешний диск (флешка, DMG «Проводник»): подпись с числами.
- [ ] Шаг строк в секции «Диски» ровный, FTP-строка той же высоты.
- [ ] Отключение FTP-тома в Finder убирает строку в течение 30 секунд.

## Вне рамок

- **Опрос настоящего свободного места по FTP** (`SITE DF`, `AVBL`, `XQUOTA`).
  Нестандартные расширения, поддержка у меньшинства серверов, а том смонтирован
  только для чтения — числу негде пригодиться.
- **Подсчёт занятого обходом каталогов сервера.** Дал бы «занято», но не
  «сколько всего», то есть полоску всё равно нарисовать нечем; на сетевом томе
  это часы обхода.
- **Скрытие FTP-тома из секции «Диски».** Строка нужна для навигации, вопрос
  только в числах.
- **Подсказка при наведении с объяснением, почему объём неизвестен.** В
  сайдбаре тултипов нет нигде; заводить их ради одного случая — отдельная
  задача.
