# Заметки к выпуску: только пропущенные версии

## Цель

Окно обновления показывает список изменений плоским списком, куда номера версий
попадают отдельными пунктами вперемешку с самими изменениями:

```
• 1.1.5
• 🖧 Иконка сервера во вкладках
• 1.1.4
• Навигация больше не раскрывается автоматически…
• 1.1.3
…
```

Пользователю на 1.1.4 показывается вся история проекта, хотя новое для него —
одна строка. Нужно показывать блоки версий **новее установленной** и только их:
на 1.1.4 это блок 1.1.5, на 1.1.1 — блоки 1.1.5, 1.1.4, 1.1.3, 1.1.2.

Накопительное тело релиза при этом остаётся: приложение спрашивает GitHub
только про `/releases/latest`, и без накопления перешагнувший через выпуск не
узнал бы о пропущенном никогда. Ломается не сбор заметок, а их разбор —
`release.sh` уже пишет заголовки `## 1.1.5`, а `ReleaseNotes.parse` про них не
знает и снимает решётки, превращая заголовок в пункт списка.

## Архитектура

### `Sources/PathwayCore/ReleaseNotes.swift`

Добавляется разбор по версиям рядом с существующим плоским.

```swift
public struct Section: Equatable, Sendable {
    public let version: AppVersion?   // nil — пункты до первого заголовка
    public let items: [String]
}

public static func sections(_ notes: String, after current: AppVersion) -> [Section]
```

`sections` режет тело по строкам вида `## 1.1.5`, разбирает номер через
`AppVersion` и отбрасывает секции с версией `<= current`. Пункты внутри секции
проходят тем же путём, что и раньше, — снятие маркеров вынесено в приватный
`item(from:)`, чтобы плоский `parse` и секционный разбор не разошлись.

Секция без распознанного номера (`version == nil`) сохраняется всегда: тело
релиза могли отредактировать руками, и текст без заголовка версии — это заметка
к самому свежему выпуску, отбросить её значило бы показать пустой поповер.

`parse` остаётся: он нужен как запасной путь и уже покрыт тестами.

### `Sources/Pathway/UpdateBadgeView.swift`

`notesList(for:)` строит не плоский `ForEach`, а секции: первая идёт без
подзаголовка (её номер уже назван в строке «Доступна версия 1.1.5»), остальные
получают подзаголовок «Ранее — 1.1.3» вторичным цветом.

Текущая версия берётся из `service.currentVersion` — поле уже публичное, вью до
него дотягивается без правок сервиса.

Пустой результат `sections` означает, что тело релиза не содержит ничего новее
установленного: показывается плоский `parse` целиком. Иначе поповер, открытый на
релизе со странным телом, оказался бы пуст при доступном обновлении.

## Поток данных

```
GitHub /releases/latest
  → ReleaseInfo.notes (накопительный Markdown с «## 1.1.5»)
  → ReleaseNotes.sections(notes, after: service.currentVersion)
  → [Section] без версий ≤ установленной
  → UpdateBadgeView.notesList: первая секция без подзаголовка, прочие с «Ранее — X»
```

`release.sh` не меняется.

## Тесты

`Tests/PathwayCoreTests/ReleaseNotesTests.swift`, к существующему сьюту:

- режет тело на секции по заголовкам `## 1.1.5`
- отбрасывает версии, равные установленной, а не только младшие
- отбрасывает все версии ниже установленной, оставляя промежуточные:
  тело 1.1.5…1.1.1 при установленной 1.1.2 даёт 1.1.5, 1.1.4, 1.1.3
- пункты до первого заголовка попадают в секцию с `version == nil` и не
  отбрасываются
- заголовок с нечисловым текстом («## Что нового») — секция без версии, а не
  выброшенная строка
- тело без единого заголовка даёт одну секцию со всеми пунктами
- заголовок без пунктов не даёт пустой секции
- тело, где всё старее установленного, даёт пустой список — вью покажет плоский
  разбор

## Ручной чек-лист

- [ ] Поповер обновления на 1.1.4 при релизе 1.1.5 показывает только «🖧 Иконка
      сервера во вкладках», без номеров версий отдельными пунктами
- [ ] Заголовок «Доступна версия 1.1.5» не дублируется подзаголовком секции
- [ ] Искусственно занизив `currentVersion` до 1.1.1, видно блоки «Ранее — 1.1.4»
      и «Ранее — 1.1.3» с их пунктами
- [ ] Длинный список по-прежнему упирается в потолок высоты и скроллится, кнопка
      «Загрузить и установить» видна

## Вне рамок

- **Отказ от накопительных заметок в `release.sh`.** Приложение читает только
  `/releases/latest`; убрав накопление, мы лишили бы перешагнувшего через выпуск
  сведений о пропущенном. Причина накопления не в оформлении, и правка разбора
  её не отменяет.
- **Запрос истории релизов у GitHub вместо накопления.** Решило бы то же самое
  честнее, но требует обновления у всех установленных копий: старые продолжат
  читать `latest`. Накопительное тело работает для уже разошедшихся версий без
  единой правки у них.
- **Рендеринг Markdown вместо разбора.** Отвергнуто раньше и по прежней причине:
  `AttributedString(markdown:)` схлопывает списки в абзац без маркеров.
- **Свёртка старых секций в раскрывающийся блок.** Лишний элемент управления
  ради случая, который у коллег редок: обновляются они обычно с предыдущей
  версии, и старых секций в поповере не будет вовсе.
