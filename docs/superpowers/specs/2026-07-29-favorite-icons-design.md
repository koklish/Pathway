# Иконки папок в избранном

## Цель

У всех пунктов секции «Избранное» стоит одна иконка — «pin». На четырёх
стандартных закладках это ещё терпимо, но после десятого закреплённого проекта
список читается только по тексту. В Проводнике Windows и в Finder боковая
панель различает пункты визуально — оттуда и ожидание.

Цель — **дать каждой закладке свою иконку**: либо SF Symbol из предложенного
набора, либо произвольный эмодзи/символ. Назначение — через контекстное меню
строки, выбор сохраняется и переживает перезапуск.

## Архитектура

### Хранение: `Favorite.icon`

`Sources/PathwayCore/FavoritesStore.swift`

Новое поле `var icon: String?`. Строка, а не enum: значение — либо имя
SF Symbol, либо эмодзи, и отличать их при записи не нужно — это забота
рендера. Enum заставил бы Core решать, что является валидным символом, а эта
проверка требует AppKit (см. ниже) и в Core невозможна.

Опционал, а не строка с умолчанием: записи, сохранённые прошлыми версиями,
ключа `icon` не имеют, `Codable` декодирует их с nil — миграция не нужна
вовсе. Значение nil означает «иконка по умолчанию» (pin), и это же состояние
кнопки «По умолчанию» в пикере.

### Мутация: `FavoritesStore.setIcon(_:icon:)`

Метод в стиле соседнего `rename`: найти по id, записать, `save()`.
Пустая и пробельная строка сводится к nil — иначе пустое поле ввода эмодзи
сохранило бы пустую строку, и рендер получил бы «заданную иконку», которую
нечем нарисовать: ни символа, ни текста.

### Рендер: валидность проверяет UI, а не Core

`Sources/Pathway/SidebarView.swift`

Вопрос «является ли строка именем SF Symbol» отвечает только
`NSImage(systemSymbolName:) != nil`, а это AppKit — в PathwayCore такой
проверке неоткуда взяться, и тащить её в Core значило бы нарушить границу
«нет типов, которые рисуют». Поэтому Core хранит строку как есть,
а `FavoriteRow` выбирает представление:

- `icon == nil` → `Image(systemName: "pin")`, как раньше;
- строка — валидный SF Symbol → `Image(systemName:)`;
- иначе → `Text(icon)` (эмодзи или произвольный символ).

Тот же выбор — в drag-preview: `Label(favorite.name, systemImage:)` заменяется
на вручную собранный `HStack` с тем же правилом, иначе перетаскиваемая строка
показывала бы pin, которого у неё уже нет.

### Пикер: лист с сеткой символов и полем эмодзи

`Sources/Pathway/FavoriteIconPicker.swift` (новый файл)

Своя вью, а не системный пикер: у macOS нет общего диалога SF Symbols
(есть только в SF Symbols.app), а пикер эмодзи (Control-⌘-Space) — глобальный
и не встраивается в лист.

Состав листа:

- сетка из ~24 заранее выбранных символов, осмысленных для папок
  (folder, star, heart, bookmark, house, briefcase, hammer, wrench,
  photo, music.note, film, gamecontroller, book, graduationcap, airplane,
  cart, gift, leaf, flame, bolt, lock, cloud, desktopcomputer, iphone);
- текстовое поле «Эмодзи или символ» — произвольная строка, туда же можно
  вставить из системного пикера эмодзи;
- кнопка «По умолчанию» — сброс в nil.

Открытие — через `@State` в `FavoriteRow` (`sheet(item:)` по id закладки):
паттерн pending-запросов из AppState здесь избыточен — пикеру нужен только
сам `Favorite` и стор, оба уже есть в строке; выносить состояние в Core ради
одного листа значило бы плодить второй канал без причины.

Пункт контекстного меню — один, «Выбрать иконку…»: сброс живёт внутри листа
кнопкой «По умолчанию», отдельный пункт «Сбросить иконку» дублировал бы её
и раздувал меню условной веткой.

## Поток данных

```
Контекстное меню FavoriteRow → «Выбрать иконку…»
  ↓ sheet
FavoriteIconPicker(favorite, store)
  ├ тап по символу сетки → store.setIcon(id, icon: "star")
  ├ ввод эмодзи + «Готово» → store.setIcon(id, icon: "🚀")
  └ «По умолчанию» → store.setIcon(id, icon: nil)
  ↓ save() → UserDefaults (ключ favorites.items)
FavoriteRow перечитывает favorite.icon (store @Observable)
  ↓
pin / Image(systemName:) / Text(эмодзи) — в строке и в drag-preview
```

## Тесты

`Tests/PathwayCoreTests/FavoritesStoreTests.swift`, сьют «Избранное»:

- **назначенная иконка переживает пересоздание стора** — `setIcon` +
  новый `FavoritesStore` на тех же defaults, `icon` на месте. Проверяет,
  что поле попало в `save()`, а не живёт только в памяти.
- **сброс возвращает иконку по умолчанию** — после `setIcon(..., "star")`
  вызов с nil даёт `icon == nil`.
- **пустая строка означает сброс, а не пустую иконку** — `setIcon(..., "  ")`
  даёт nil. Фиксирует нормализацию: без неё рендер получил бы строку,
  которую нечем нарисовать.
- **запись прошлой версии декодируется без иконки, а не ломает загрузку** —
  `seedStored` пишет JSON без ключа `icon` (ручная сборка словаря, как это
  сделал бы старый энкодер), стор читает его, `icon == nil`. Без этого теста
  обязательное поле в будущей правке молча уронило бы всё избранное
  в пустой список.

Валидность имён SF Symbol тестами не покрывается: проверка — `NSImage` на
стороне UI, а UI-тестов в проекте нет принципиально.

## Ручной чек-лист

- [ ] Контекстное меню закладки → «Выбрать иконку…» → лист с сеткой символов.
- [ ] Выбор «star» в сетке: иконка строки меняется, лист закрывается.
- [ ] Ввод «🚀» в поле: строка показывает эмодзи.
- [ ] «По умолчанию»: возврат к pin.
- [ ] Перезапуск приложения: назначенные иконки на месте.
- [ ] Перетаскивание закладки с назначенной иконкой: preview показывает её,
      а не pin.
- [ ] Строка с эмодзи той же высоты, что и соседние — шаг секции не ломается.

## Вне рамок

- **Цвет иконки.** Второй параметр выбора, отдельная задача; сейчас иконки
  остаются серыми, как pin.
- **Поиск по всему каталогу SF Symbols.** Полного списка имён в публичном API
  нет; встраивать выгрузку из SF Symbols.app — тысячи строк данных ради
  редкого действия.
- **Иконки для «Мест» и «Сети».** Там иконки уже осмысленные (системные и
  по типу сервера), настраивать нечего.
- **Синхронизация иконок между машинами.** UserDefaults локальны, как и весь
  список избранного.
