# Операция «Свойства» файлов

## Цель

Дать пользователю окно наблюдения за выделенным — как «Свойства» в Проводнике Windows. Свой диалог (не проброс в Finder), только чтение, для одного элемента, папки и группы. Размер папки и группы считается рекурсивно с прогрессом в реальном времени. Открывается листом поверх окна, закрывается Esc.

Команда `properties` в реестре, шорткат `⌘I` (как в Finder и Windows), пункт в меню «Файл» и в контекстном меню списка.

## Архитектура

Фича следует уже принятой в проекте раскладке: чистая логика в `PathwayCore`, вью в `Pathway`, обратный канал через `AppState.pending…`, подсчёт — отменяемой фоновой задачей с проверкой актуальности.

### `PathwayCore/FileProperties.swift` — модель данных диалога

Три чистых типа плюс сборщик. Без AppKit-рисующих типов, без SwiftUI.

```swift
/// Что показывает диалог свойств. Собирается из выделения в момент открытия —
/// снимок, а не ссылка на живую модель: список под листом может смениться.
public enum PropertiesSubject: Sendable {
    case single(FileProperties)     // один файл или папка
    case group(GroupProperties)     // несколько элементов
}

/// Свойства одного элемента. Строки уже отформатированы в Core — UI их только
/// показывает (как errorMessage: текст рождается в Core).
public struct FileProperties: Sendable {
    public let url: URL
    public let name: String
    public let isDirectory: Bool
    public let kind: String            // «Документ PDF», «Папка», «Приложение»
    public let location: String        // путь родительской папки, ~ сокращён
    public let created: String?        // отформатированная дата, nil → «—»
    public let modified: String?
    public let access: String          // «Чтение и запись» / «Только чтение»
    /// Для файла — размер известен сразу. Для папки — nil, считается фоном.
    public let immediateSize: Int64?
}

/// Свойства группы: сводка, без имени/дат/прав — они для группы бессмысленны.
public struct GroupProperties: Sendable {
    public let count: Int
    public let location: String        // общая папка или «Разные папки»
    public let kinds: String           // общий тип или «Файлы разных типов»
}
```

Сборщик — статические функции, синхронные, без обращения к диску сверх того, что уже в `FileItem` (метаданные уже загружены к моменту, когда есть выделение):

```swift
public enum PropertiesBuilder {
    public static func subject(for items: [FileItem]) -> PropertiesSubject
    // single: kind через UTType, access через isWritableFile, даты через
    //         resourceValues(.creationDateKey/.contentModificationDateKey)
    // group: общий location, если у всех один родитель; общий kind, если
    //        расширения совпадают
}
```

**Тип (`kind`) — через `UTType`, а не как в списке файлов.** `BrowserModel.kindLabel` даёт грубое «PDF» (расширение заглавными) — для колонки этого хватает. В свойствах нужен человеческий `localizedDescription` из `UTType(filenameExtension:)` («Документ PDF»). Папку и приложение отличаем по `isDirectory` и расширению `.app`.

**Даты — `.long` дата + `.shortened` время**, а не `.abbreviated` как в колонке: в свойствах место есть, и полная дата читается лучше. Форматирование — в Core, рядом со сборщиком.

**`access`** — из `FileManager.isWritableFile(atPath:)`: «Чтение и запись», иначе «Только чтение». Строкой, не редактируется (см. Вне рамок).

### `PathwayCore/DirectorySizeCounter.swift` — рекурсивный подсчёт с прогрессом

Отдельный тип, потому что это единственная в фиче механика с диском и отменой. Не метод `BrowserModel`: подсчёт живёт ровно столько, сколько открыт лист, и имеет собственный жизненный цикл.

```swift
/// Промежуточный итог обхода. Растёт по мере чтения дерева.
public struct SizeProgress: Sendable, Equatable {
    public var totalSize: Int64
    public var fileCount: Int
    public var folderCount: Int
}

@MainActor
public final class DirectorySizeCounter: ObservableObject {
    @Published public private(set) var progress = SizeProgress(...)
    @Published public private(set) var isFinished = false

    /// Запускает обход переданных корней. Повторный вызов отменяет прежний.
    public func start(roots: [URL])
    /// Останавливает обход. Зовётся при закрытии листа.
    public func cancel()
}
```

Реализация повторяет технику `DirectoryLoader`:

- Обход в `Task.detached(.utility)` — приоритет ниже интерактивного, как третья ступень загрузки каталога.
- По дереву — рекурсивным `opendir/readdir` с типом из `d_type`, **не** `FileManager.enumerator` и **не** `URL`-обходом: замеры в CLAUDE.md показывают 4824 мс против 0.7 мс на `URL` против `readdir` из-за похода на диск за типом. Размер файла — `lstat` (символические ссылки не разыменовываем и по ним не спускаемся: иначе цикл ссылок зациклит обход).
- Итог копится в фоне, а в `@Published progress` сливается **раз в ~200 мс, а не на каждый файл**: на SMB тысячи мелких обновлений захлебнули бы главный поток. Порог по времени, накопленное отдаётся целиком.
- **Отмена кооперативная и двойная, как в `reloadAsync`:** `Task.cancel()` при `start`/`cancel` плюс проверка `Task.isCancelled` в цикле обхода — уже запущенный `Task.detached` отмену видит только через флаг.

Для одного файла счётчик не запускается — размер берётся из `FileProperties.immediateSize`. Запуск только когда среди субъекта есть папка (single-папка или любая группа).

### Обратный канал

`AppState.pendingProperties: PropertiesSubject?` — по образцу `pendingCompress`. Команда `properties` его выставляет, лист читает и сбрасывает на закрытии.

Счётчик `DirectorySizeCounter` живёт **во вью-листе** (`@StateObject`), а не в `AppState`: он привязан к времени жизни листа, `start` на `.onAppear`, `cancel` на `.onDisappear`. В `AppState` держать нельзя — пришлось бы вручную гасить при закрытии, а лист уже даёт это даром.

### Команда в реестре

`Commands.swift`: новый `case properties` в группе «Файл», в `CommandRegistry.all`:

```swift
AppCommand(
    id: .properties,
    title: "Свойства",
    shortcut: Shortcut(.character("i"), .command),
    icon: "info.circle",
    isEnabled: { !$0.isEditingText && !$0.browser.selectedItems.isEmpty },
    run: { $0.pendingProperties = PropertiesBuilder.subject(for: $0.browser.selectedItems) }
)
```

Не в `writesToDisk` — только чтение, работает и на томе только для чтения. Гаснет при вводе текста (флаг `isEditingText`) и на пустом выделении.

`⌘I` в проекте свободно (проверено: ни одна команда реестра и ни один пункт `AppCommands`/`PathwayApp` его не занимают). Стандартного системного пункта с `⌘I` в SwiftUI-меню нет — команда берёт сочетание как обычная в реестре, через `CommandGroup`, без перехвата у текстовых полей. В ручной чек-лист вынесена только финальная проверка живьём.

### Вью

`Pathway/PropertiesDialog.swift` — `PropertiesDialogView`, по образцу `CompressDialogView`:

- `let subject: PropertiesSubject`, `let dismiss: () -> Void`.
- `@StateObject private var counter = DirectorySizeCounter()`.
- `.onAppear`: если субъект содержит папку — `counter.start(roots:)`. `.onDisappear`: `counter.cancel()`.
- Строки-поля: подпись слева серым, значение справа (как поля `CompressDialogView`). Размер: для файла — статичная строка из `immediateSize`; для папки/группы — `ByteCountFormatter.string(...)` от `counter.progress.totalSize`, плюс строка «Содержимое: N объектов (файлов: X, папок: Y)», плюс маленький индикатор, пока `!counter.isFinished`.
- Кнопка «Готово» и Esc закрывают. `isEditingText` этот лист не поднимает — редактируемых полей нет.

Монтируется в `MainWindow.swift` рядом с листом архивации:

```swift
.sheet(isPresented: Binding(
    get: { appState.pendingProperties != nil },
    set: { if !$0 { appState.pendingProperties = nil } }
)) {
    if let subject = appState.pendingProperties {
        PropertiesDialogView(subject: subject) { appState.pendingProperties = nil }
    }
}
```

Пункт контекстного меню — в `FileListView.menuNeedsUpdate`, оформление из реестра (`CommandRegistry[.properties]`), как остальные пункты.

## Поток данных

1. Пользователь выделяет элементы, жмёт `⌘I` / пункт меню.
2. `run` зовёт `PropertiesBuilder.subject(for:)` — синхронно собирает снимок из `selectedItems`, кладёт в `AppState.pendingProperties`.
3. `.sheet` показывает `PropertiesDialogView`. Поля имени/типа/дат/прав видны сразу.
4. Если есть папка — `.onAppear` запускает `counter.start`. Фоновый обход шлёт `progress` раз в ~200 мс; размер и счётчик содержимого растут на глазах. По завершении `isFinished = true`, индикатор исчезает.
5. Закрытие (Готово/Esc) → `.onDisappear` → `counter.cancel()` останавливает обход → `pendingProperties = nil`.

## Тесты (`PathwayCore`)

Покрывается только Core; вью — ручным чек-листом.

**`FilePropertiesTests`** (`PropertiesBuilder`):
- один файл → `.single`, `immediateSize` равен размеру файла, `kind` не пустой
- одна папка → `.single`, `immediateSize == nil` (считается фоном, а не берётся из `FileItem`)
- два файла в одной папке → `.group`, `count == 2`, `location` — их общая папка
- файлы из разных папок → `location == "Разные папки"`
- файлы с одним расширением → общий `kind`; с разными → «Файлы разных типов»
- права: файл только для чтения → `access == "Только чтение"` (снять флаг записи в temp-файле)
- даты: файл без даты создания не роняет сборщик, поле `nil`

**`DirectorySizeCounterTests`**:
- пустая папка → `totalSize == 0`, `fileCount == 0`, `isFinished` становится true
- папка с известным содержимым (создать N файлов заданного размера) → `totalSize` равен сумме, `fileCount == N`
- вложенные папки → рекурсивно суммирует, `folderCount` считает подпапки
- `cancel()` до завершения → обход останавливается, `isFinished` не станет true задним числом
- несколько корней (`roots` из двух папок) → суммирует оба
- символическая ссылка на родителя не зацикливает обход (по ссылкам не спускаемся)

Осторожно с URL: сравнения строить от канонизированных путей (`/var`→`/private/var`), выделение — от `model.items[…].url`, как предупреждает CLAUDE.md. `withTempDir`/`withTempDirAsync` из `DirectoryLoaderTests.swift`.

## Ручной чек-лист

- [ ] `⌘I` на файле открывает лист; тип, путь, размер, даты, доступ верны
- [ ] `⌘I` на папке: размер и «Содержимое» растут в реальном времени, индикатор гаснет по завершении
- [ ] `⌘I` на группе: «Выделено объектов: N», суммарный размер считается, расположение и типы верны
- [ ] Закрытие листа во время обхода большой папки останавливает подсчёт (проверить, что фоновая нагрузка спадает)
- [ ] Esc и «Готово» закрывают лист
- [ ] `⌘I` в адресной строке / при инлайн-переименовании не срабатывает (гасится `isEditingText`)
- [ ] Пункт есть в меню «Файл» и в контекстном меню списка, с иконкой и шорткатом
- [ ] На пустом выделении (клик по пустому месту) команда недоступна
- [ ] На томе только для чтения `⌘I` работает
- [ ] `⌘I` не перехвачен стандартным системным пунктом меню
- [ ] Права: файл с снятым флагом записи показывает «Только чтение»

## Вне рамок

- **Проброс в системное окно Finder (Cmd+I через AppleScript)** — отвергнут: требует разрешения на автоматизацию, окно чужого вида, несколько окон на группу. Проект последовательно делает свои реализации (`TerminalLauncher` через `open -a` ровно ради обхода разрешений).
- **Редактирование в диалоге (имя, атрибуты, права)** — отвергнуто: переименование уже есть отдельной командой (F2), скрытость — это точка в имени (то же переименование), а корректный `chmod` (владелец/группа/остальные, наследование) — работа сравнимая со всей фичей. Свойства остаются окном наблюдения.
- **Отдельное немодальное окно / инспектор-панель** — отвергнуты: в проекте нет `Window` кроме главного, `AppState.browser` завязан на активную вкладку, а панель-инспектор — уже другая фича, конкурирующая за ширину окна.
- **Версия приложения из `Info.plist` для `.app`** — не показываем: пользователь подтвердил, что предложенного состава полей достаточно.
- **Кэширование размера папки между открытиями** — не делаем: том мог смениться, содержимое — тоже; свежий обход надёжнее и уже быстр благодаря `readdir`.
