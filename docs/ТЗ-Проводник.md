## 1. Общие сведения

### 1.1. Наименование системы

Полное наименование: **файловый менеджер «Проводник» для операционной системы macOS**.

Внутреннее (проектное) обозначение — **Pathway**. Обозначение используется в исходном коде, идентификаторе пакета (`com.pathway.filemanager`), именах модулей и служебных скриптах. Пользователю во всех элементах интерфейса, в имени приложения и в системных диалогах видно наименование **«Проводник»**.

Разделение намеренное: латинское проектное имя избавляет от кириллицы в путях сборки, именах таргетов и идентификаторах, а русское отображаемое имя сразу сообщает пользователю назначение программы.

### 1.2. Основание для разработки

Разработка ведётся по инициативе владельца продукта. Формальный договор отсутствует, приёмку выполняет владелец продукта единолично.

### 1.3. Плановые сроки

Разработка ведётся итерационно, без фиксированной даты завершения. Порядок выпуска версий определён в разделе 13.

### 1.4. Порядок оформления результатов

Результат работы — исходный код в репозитории Git, собранное приложение в формате `.app`, опубликованный релиз с архивом и заметками к выпуску, а также комплект проектной документации (спецификации в `docs/superpowers/specs/`).

### 1.5. Термины и сокращения

| Термин | Определение |
|---|---|
| **Система** | Разрабатываемый файловый менеджер «Проводник» |
| **Панель** | Область главного окна, отображающая содержимое одного каталога |

## 2. Назначение и цели создания системы

### 2.1. Назначение

Система предназначена для навигации по файловой системе рабочей станции под управлением macOS и выполнения повседневных операций с файлами и каталогами — в модели взаимодействия, привычной пользователям Проводника Windows.

### 2.2. Обоснование разработки

Штатный файловый менеджер macOS (Finder) реализует иную модель взаимодействия, чем Проводник Windows. Для сотрудников, перешедших на macOS с Windows, ключевыми затруднениями являются:

1. **Отсутствие постоянно видимой адресной строки.** Полный путь к текущему каталогу в Finder не отображается и не редактируется напрямую; переход по введённому пути требует отдельного модального диалога.
2. **Отсутствие полноценного дерева каталогов.** Боковая панель Finder содержит плоский список закладок, а не раскрываемое дерево от корня файловой системы.
3. **Иная модель перемещения файлов.** Операция «вырезать» в привычном виде (⌘X → ⌘V) в Finder отсутствует; перемещение выполняется сочетанием ⌥⌘V либо перетаскиванием.
4. **Отсутствие переименования по клавише F2.**

Перечисленные различия не устраняются настройками Finder и не покрываются его расширениями.

### 2.3. Цели создания

**Основная цель:** предоставить пользователям macOS файловый менеджер, воспроизводящий модель взаимодействия Проводника Windows, при сохранении полной интеграции с нативными механизмами macOS (Корзина, Quick Look, буфер обмена, монтирование сетевых томов, системные иконки).

**Частные цели:**

- **Ц1.** Сократить время на навигацию к каталогу с известным путём за счёт редактируемой адресной строки и дерева каталогов.
- **Ц2.** Устранить необходимость переключения между Finder и сторонними утилитами для операций с архивами, поиска по содержимому файлов и пакетного переименования.
- **Ц3.** Обеспечить приемлемую скорость работы с сетевыми томами (SMB, FTP), где штатные средства демонстрируют задержки, несовместимые с интерактивной работой.
- **Ц4.** Обеспечить самостоятельное обновление системы у пользователей без участия администратора и без обращений к службе поддержки.

### 2.4. Критерий достижения целей

Система признаётся достигшей целей, если пользователи, участвовавшие в опытной эксплуатации, используют её вместо Finder для повседневной навигации и файловых операций, не прибегая к Finder для задач, входящих в объём системы.

## 3. Характеристика объекта автоматизации

### 3.1. Объект автоматизации

Объектом автоматизации является деятельность пользователя рабочей станции по работе с файловыми ресурсами: локальными дисками, внешними и сетевыми томами.

### 3.2. Условия эксплуатации

| Параметр | Значение |
|---|---|
| Операционная система | macOS 15 (Sequoia) и выше |
| Архитектура процессора | Apple Silicon (arm64) |
| Оперативная память | не менее 8 ГБ |
| Дисковое пространство | не более 50 МБ под приложение |
| Сетевое окружение | локальная сеть организации, серверы SMB и FTP |
| Права пользователя | обычный пользователь; права администратора требуются однократно для выдачи полного доступа к диску |

### 3.3. Категории пользователей

Единственная категория — **пользователь рабочей станции**. Разделение прав внутри системы не предусматривается: система работает от имени пользователя операционной системы и наследует его права на файловые объекты. Административного интерфейса, ролей и учётных записей внутри системы нет.

Предполагаемый уровень подготовки: уверенный пользователь ПК, имеющий опыт работы с Проводником Windows. Специальная подготовка для работы с системой не требуется; знакомство с возможностями обеспечивается встроенным обучающим туром (см. п. 5.13).

### 3.4. Сведения об объёме обрабатываемых данных

| Показатель | Значение |
|---|---|
| Объектов в одном каталоге | до 50 000 |
| Глубина дерева каталогов | не ограничена |
| Одновременно открытых вкладок | до 20 |
| Одновременно подключённых сетевых томов | до 10 |
| Размер обрабатываемых файлов | не ограничен (ограничения применяются только к операциям чтения содержимого, см. п. 5.5) |

## 4. Требования к системе в целом

### 4.1. Требования к структуре системы

**ТР-СТР-01.** Система реализуется как одно приложение macOS (`.app`), не требующее установки серверных компонентов, служб или агентов.

**ТР-СТР-02.** Система состоит из трёх модулей сборки:

| Модуль | Тип | Назначение |
|---|---|---|
| `PathwayCore` | библиотека | Бизнес-логика, модели данных, взаимодействие с ОС |
| `Pathway` | исполняемый | Пользовательский интерфейс |
| `PathwayCoreTests` | тестовый | Автоматизированные проверки `PathwayCore` |

**ТР-СТР-03.** Направление зависимостей — строго от интерфейса к ядру. Модуль `PathwayCore` не должен зависеть от модуля `Pathway`.

**ТР-СТР-04.** Модуль `PathwayCore` не должен содержать типов, отвечающих за отрисовку интерфейса. Импорт UI-фреймворка SwiftUI в ядре не допускается.

**ТР-СТР-05.** Допускается использование в ядре системных сервисов платформы (доступ к рабочему столу, буферу обмена, механизму межпроцессного взаимодействия), не связанных с отрисовкой.

**ТР-СТР-06.** Внешние зависимости (сторонние библиотеки) не используются. Вся функциональность реализуется средствами стандартной библиотеки и системных фреймворков.

### 4.2. Требования к режимам функционирования

**ТР-РЕЖ-01.** Система функционирует в единственном режиме — интерактивном, по запросу пользователя. Фоновых, пакетных и автоматических режимов работы без участия пользователя не предусматривается.

**ТР-РЕЖ-02.** Допускается выполнение отдельных операций (загрузка каталога, поиск, архивация, подсчёт размера, проверка обновлений) в фоновых потоках при сохранении отзывчивости интерфейса.

### 4.3. Требования к численности и квалификации персонала

Обслуживающий персонал не требуется. Развёртывание и обновление выполняются самой системой (см. раздел 11).

### 4.4. Требования к эргономике

**ТР-ЭРГ-01.** Язык интерфейса — русский. Все элементы интерфейса, сообщения об ошибках, подсказки и системные уведомления оформляются на русском языке.

**ТР-ЭРГ-02.** Системные каталоги, физически именованные латиницей (`Desktop`, `Documents`, `Downloads`, `Pictures`, `Music`, `Movies`, `Library`, `Public`, `Applications`), отображаются пользователю на русском языке. Физические имена при этом не изменяются.

**ТР-ЭРГ-03.** Система поддерживает светлое и тёмное оформление, следуя системной настройке. Собственного переключателя темы не предусматривается.

**ТР-ЭРГ-04.** Все команды, доступные через меню, должны иметь единообразное представление: одинаковый заголовок, значок и сочетание клавиш во всех местах, где команда доступна (главное меню, контекстное меню, панель инструментов).

### 4.5. Требования к защите информации

**ТР-ЗАЩ-01.** Система не передаёт пользовательские данные за пределы рабочей станции. Единственное сетевое взаимодействие, инициируемое системой самостоятельно, — обращение к сервису публикации релизов для проверки наличия обновления (см. п. 5.12).

**ТР-ЗАЩ-02.** Учётные данные для доступа к сетевым серверам хранятся в зашифрованном виде. Требования к шифрованию — в разделе 9.

**ТР-ЗАЩ-03.** Система не ведёт журналов действий пользователя, не собирает телеметрию и не отправляет отчёты об ошибках.

### 4.6. Требования к сохранности данных

**ТР-СОХР-01.** Удаление файловых объектов выполняется исключительно перемещением в системную Корзину. Безвозвратное удаление средствами системы не реализуется.

**ТР-СОХР-02.** Операции, способные привести к потере данных (перезапись существующего файла), выполняются только после явного подтверждения пользователя.

**ТР-СОХР-03.** При отказе в ходе групповой операции уже выполненная её часть не откатывается; пользователю сообщается число обработанных объектов.

### 4.7. Требования к сохраняемому состоянию

**ТР-СОСТ-01.** Между запусками системы сохраняются:

- список открытых вкладок с путями и признаком закрепления;
- список избранного с пользовательскими значками и порядком;
- параметры сортировки списка файлов;
- признак завершения обучающего тура;
- закладки сетевых серверов и учётные данные к ним;
- дата последней проверки обновлений.

**ТР-СОСТ-02.** Между запусками системы **не** сохраняются:

- признак отображения скрытых файлов;
- режим поиска по содержимому файлов;
- история навигации вкладок;
- список смонтированных сетевых томов.

Несохранение режима поиска по содержимому обусловлено его высокой стоимостью: включённый в предыдущем сеансе и забытый, он привёл бы к необъяснимо медленному поиску при следующем запуске. Несохранение списка смонтированных томов обусловлено тем, что за время простоя системы том мог быть отключён; вместо восстановления списка из хранилища выполняется опрос фактически смонтированных томов средствами ОС.

## 5. Функциональные требования

Требования сгруппированы по функциональным подсистемам. Каждое требование имеет уникальный идентификатор вида `ТР-<ПОДСИСТЕМА>-<номер>`.

### 5.1. Подсистема навигации

#### 5.1.1. Отображение содержимого каталога

**ТР-НАВ-01.** Система отображает содержимое текущего каталога в виде таблицы со следующими колонками: имя, дата изменения, размер, тип.

**ТР-НАВ-02.** Для каталогов в колонке размера значение не отображается. Размер каталога подсчитывается только по явному запросу (см. п. 5.10).

**ТР-НАВ-03.** Тип объекта отображается человекочитаемым наименованием, полученным из системного реестра типов, а не расширением файла.

**ТР-НАВ-04.** Каждому объекту отображается системный значок, соответствующий его типу. Для приложений и объектов с собственным значком отображается их собственный значок.

**ТР-НАВ-05.** Символические ссылки визуально отличаются от обычных объектов. Переход по ссылке выполняется к целевому объекту. Ссылки с недостижимой целью отображаются, но не открываются.

**ТР-НАВ-06.** Скрытые объекты (имя начинается с точки, а также помеченные системным атрибутом скрытия) по умолчанию не отображаются. Отображение включается командой «Показывать скрытые файлы» (⌘⇧.).

#### 5.1.2. Сортировка

**ТР-НАВ-07.** Список сортируется по любой из колонок в обоих направлениях. Направление и колонка переключаются щелчком по заголовку колонки.

**ТР-НАВ-08.** Каталоги всегда располагаются перед файлами независимо от выбранной сортировки.

**ТР-НАВ-09.** Сортировка по умолчанию — по дате изменения, от новых к старым. Выбор обусловлен наиболее частым сценарием: обращением к недавно изменённым файлам.

**ТР-НАВ-10.** Выбранная сортировка сохраняется между запусками системы и применяется ко всем вкладкам.

**ТР-НАВ-11.** Сортировка по имени учитывает числовые фрагменты как числа: «файл 2» располагается перед «файл 10».

#### 5.1.3. Адресная строка

**ТР-НАВ-12.** Система отображает полный путь к текущему каталогу в виде последовательности сегментов («хлебных крошек»). Щелчок по сегменту выполняет переход к соответствующему каталогу.

**ТР-НАВ-13.** Адресная строка переключается в режим редактирования по команде «Перейти к папке…» (⌘L) либо щелчком по свободной области строки. В режиме редактирования отображается полный текстовый путь.

**ТР-НАВ-14.** Ввод пути завершается клавишей Enter (переход) или Esc (отмена с восстановлением прежнего пути).

**ТР-НАВ-15.** При вводе пути система предлагает автодополнение по существующим каталогам.

**ТР-НАВ-16.** Ввод пути допускает сокращение домашнего каталога символом `~`, а также ввод сетевых адресов вида `smb://сервер/ресурс` и `ftp://сервер`. При вводе сетевого адреса выполняется подключение к серверу (см. п. 5.7).

**ТР-НАВ-17.** Ввод несуществующего пути не выполняет переход и сообщает об этом пользователю.

#### 5.1.4. История навигации

**ТР-НАВ-18.** Система ведёт историю переходов текущей вкладки и обеспечивает перемещение по ней: «Назад» (⌘[), «Вперёд» (⌘]).

**ТР-НАВ-19.** Переход к родительскому каталогу выполняется командой «Вверх» (⌘↑). В корневом каталоге команда недоступна.

**ТР-НАВ-20.** История навигации у каждой вкладки собственная.

#### 5.1.5. Дерево каталогов

**ТР-НАВ-21.** Боковая панель содержит дерево каталогов от корня файловой системы с раскрытием узлов по требованию.

**ТР-НАВ-22.** Содержимое узла дерева загружается в момент первого раскрытия, а не при построении дерева.

**ТР-НАВ-23.** Выбор узла дерева выполняет переход к соответствующему каталогу в активной вкладке.

**ТР-НАВ-24.** Боковая панель содержит секции: «Избранное», «Этот компьютер» (тома и дерево), «Сеть» (серверы).

#### 5.1.6. Избранное

**ТР-НАВ-25.** Пользователь добавляет текущий каталог в избранное командой «Добавить в избранное» (⌘D). Повторное выполнение команды удаляет каталог из избранного.

**ТР-НАВ-26.** Порядок элементов избранного изменяется перетаскиванием.

**ТР-НАВ-27.** Элементу избранного назначается пользовательский значок: символ из системного набора либо эмодзи. При отсутствии назначенного значка отображается значок по умолчанию.

**ТР-НАВ-28.** Записи избранного, созданные предыдущими версиями системы и не содержащие сведений о значке, должны читаться без ошибок и миграции данных.

#### 5.1.7. Слежение за каталогом

**ТР-НАВ-29.** Система отслеживает изменения в отображаемом каталоге средствами ОС и обновляет список без действий пользователя.

**ТР-НАВ-30.** При обновлении списка по внешнему событию текущее выделение сохраняется для тех объектов, которые продолжают существовать.

**ТР-НАВ-31.** При обновлении списка позиция прокрутки не изменяется.

**ТР-НАВ-32.** Если отображаемый каталог удалён или стал недоступен, система выполняет автоматический переход к ближайшему существующему родительскому каталогу и сообщает об этом.

### 5.2. Подсистема вкладок

**ТР-ВКЛ-01.** Система поддерживает одновременную работу с несколькими каталогами в рамках одного окна посредством вкладок.

**ТР-ВКЛ-02.** Каждая вкладка обладает независимыми: текущим каталогом, историей навигации, выделением, позицией прокрутки и кэшем содержимого каталогов.

**ТР-ВКЛ-03.** Новая вкладка создаётся командой «Новая вкладка» (⌘T), двойным щелчком с удержанием ⌘ по каталогу, щелчком средней кнопки мыши по каталогу, а также командой контекстного меню «Открыть в новой вкладке».

**ТР-ВКЛ-04.** Одиночный щелчок с удержанием ⌘ по строке списка не создаёт вкладку: это сочетание зарезервировано системой за добавлением строки к выделению.

**ТР-ВКЛ-05.** Вкладка закрывается командой «Закрыть вкладку» (⌘W) либо щелчком по кнопке закрытия. Единственная вкладка не закрывается: закрытие оставило бы приложение без содержимого окна.

**ТР-ВКЛ-06.** Контекстное меню вкладки содержит команды: закрыть, закрыть другие, закрыть вкладки справа, закрепить/открепить.

**ТР-ВКЛ-07.** Закреплённая вкладка отображается в сокращённом виде (только значок), располагается левее незакреплённых и не закрывается командами группового закрытия.

**ТР-ВКЛ-08.** Переключение между вкладками выполняется командами «Следующая вкладка» (⌃Tab) и «Предыдущая вкладка» (⌃⇧Tab).

**ТР-ВКЛ-09.** Ширина вкладок сокращается при увеличении их числа; заголовок усекается с многоточием. Минимальная ширина обеспечивает читаемость значка и кнопки закрытия.

**ТР-ВКЛ-10.** Состав вкладок сохраняется между запусками системы. Содержимое каталога восстановленной вкладки загружается при первом её отображении, а не при восстановлении: одновременная загрузка всех вкладок на сетевом томе привела бы к неприемлемой задержке запуска.

**ТР-ВКЛ-11.** Признак необходимости загрузки хранится отдельно от факта пустоты списка: пустой каталог также даёт пустой список, и различение по этому признаку приводило бы к повторной загрузке при каждом переключении.

### 5.3. Подсистема файловых операций

#### 5.3.1. Основные операции

**ТР-ФО-01.** Система выполняет следующие операции с файловыми объектами:

| Операция | Сочетание клавиш | Примечание |
|---|---|---|
| Копировать | ⌘C | Через системный буфер обмена |
| Вырезать | ⌘X | Отметка объектов; перемещение — при вставке |
| Вставить | ⌘V | Копирование либо перемещение |
| Переместить в Корзину | ⌘⌫ | Безвозвратное удаление не реализуется |
| Переименовать | F2 | Редактирование по месту |
| Переименовать выбранные | ⌃⌘R | Пакетное, от двух объектов |
| Создать папку | ⇧⌘N | С автонумерацией имени |
| Открыть | ⌘↓ | Приложением по умолчанию |
| Выбрать всё | ⌘A | |
| Копировать путь | ⌥⌘C | Текстовый путь в буфер |
| Свойства | ⌘I | |
| Быстрый просмотр | Пробел | Системный механизм предпросмотра |
| Показать в Finder | ⇧⌘R | |
| Открыть в Терминале | ⇧⌘T | |
| Обновить | ⌘R | Принудительное перечитывание каталога |

**ТР-ФО-02.** Операции копирования и перемещения выполняются асинхронно и не блокируют интерфейс.

**ТР-ФО-03.** Буфер обмена системы совместим с Finder в обоих направлениях: объекты, скопированные в Finder, вставляются в системе и наоборот.

**ТР-ФО-04.** Команда «Копировать путь» помещает в буфер текстовое представление пути. При пустом выделении копируется путь текущего каталога. Перед записью текста буфер очищается: иначе ранее скопированные ссылки на файлы остались бы в буфере и следующая вставка скопировала бы сам файл вместо текста.

#### 5.3.2. Вырезание и вставка

**ТР-ФО-05.** Команда «Вырезать» помечает объекты и помещает ссылки на них в буфер обмена; физическое перемещение выполняется в момент вставки.

**ТР-ФО-06.** Помеченные объекты отображаются с пониженной непрозрачностью.

**ТР-ФО-07.** Пометка снимается клавишей Esc, выполнением вставки либо новой операцией копирования.

**ТР-ФО-08.** Объект, исчезнувший до момента вставки, пропускается без прерывания операции.

#### 5.3.3. Разрешение конфликтов имён

**ТР-ФО-09.** При совпадении имени вставляемого объекта с существующим система предлагает пользователю выбор: заменить, оставить оба (с автоматическим переименованием), пропустить.

**ТР-ФО-10.** Выбор пользователя применяется либо к одному объекту, либо ко всем оставшимся конфликтам операции по его указанию.

#### 5.3.4. Переименование по месту

**ТР-ФО-11.** Переименование выполняется редактированием имени непосредственно в строке списка.

**ТР-ФО-12.** При начале редактирования выделяется имя без расширения.

**ТР-ФО-13.** Корректность нового имени проверяется до применения: пустое имя, занятое имя и имя с недопустимыми символами отклоняются с сообщением.

**ТР-ФО-14.** Редактирование прерывается клавишей Esc без применения изменений.

**ТР-ФО-15.** Одновременное переименование по месту более одного объекта не поддерживается: редактор в списке единственный. Для нескольких объектов применяется пакетное переименование.

#### 5.3.5. Перетаскивание

**ТР-ФО-16.** Система поддерживает перетаскивание объектов: внутри списка на каталог-приёмник, из списка на узел дерева каталогов, из списка в Finder и обратно.

**ТР-ФО-17.** Каталог-приёмник подсвечивается при наведении перетаскиваемого объекта.

**ТР-ФО-18.** Перетаскивание с удержанием клавиши ⌥ выполняет копирование вместо перемещения.

**ТР-ФО-19.** Перетаскивание объекта в собственный родительский каталог, в самого себя или во вложенный в себя каталог не выполняется.

#### 5.3.6. Тома только для чтения

**ТР-ФО-20.** На томе, смонтированном только для чтения, команды, изменяющие содержимое диска, недоступны: создание папки, переименование (одиночное и пакетное), перемещение в Корзину, вставка, вырезание, архивирование.

**ТР-ФО-21.** Архивирование включено в перечень изменяющих команд, поскольку архив создаётся рядом с исходными объектами, а не во временном каталоге.

### 5.4. Подсистема пакетного переименования

**ТР-ПАК-01.** Система обеспечивает переименование группы выбранных объектов по единому правилу. Команда доступна при выделении не менее двух объектов.

**ТР-ПАК-02.** Правило переименования складывается из следующих компонентов:

| Компонент | Назначение |
|---|---|
| Найти / Заменить | Замена подстроки в имени |
| Регистр | Приведение к верхнему, нижнему регистру, либо без изменения |
| Префикс | Добавление текста в начало имени |
| Суффикс | Добавление текста в конец имени |
| Нумерация | Добавление порядкового номера с указанием начального значения, шага и числа разрядов |

**ТР-ПАК-03.** Все компоненты правила применяются к имени без расширения. Расширение сохраняется неизменным во всех случаях.

**ТР-ПАК-04.** Порядок применения компонентов фиксирован: замена → регистр → префикс и суффикс → нумерация. Нумерация применяется последней, поскольку номер должен присоединяться к окончательному имени.

**ТР-ПАК-05.** Поле «Найти» выполняет двойную функцию: задаёт подстроку для замены и отбирает объекты. Объект, имя которого не содержит указанной подстроки, в операцию не включается вовсе — не отображается в предварительном просмотре, не учитывается в счётчике и не занимает порядковый номер.

**ТР-ПАК-06.** Пустое поле «Найти» не отбирает объекты: правило применяется ко всему выделению. Данное поведение необходимо для сценария добавления префикса ко всем выбранным объектам.

**ТР-ПАК-07.** Отбор объектов выполняется по имени без расширения — по тому же тексту, к которому применяется замена.

**ТР-ПАК-08.** Порядковый номер при нумерации назначается в порядке отображения объектов в списке (с учётом текущей сортировки), а не в порядке имён.

**ТР-ПАК-09.** Система отображает предварительный просмотр результата: для каждого объекта — прежнее и новое имя. Просмотр пересчитывается при каждом изменении правила.

**ТР-ПАК-10.** Конфликты выявляются до выполнения операции и отображаются с указанием причины:

| Причина конфликта | Условие |
|---|---|
| Пустое имя | Правило даёт имя нулевой длины |
| Недопустимые символы | Имя содержит символы, запрещённые файловой системой |
| Совпадение целевых имён | Два объекта получают одинаковое новое имя |
| Имя занято на диске | Целевое имя принадлежит существующему объекту |

**ТР-ПАК-11.** При проверке занятости имени на диске имена других переименовываемых объектов занятыми не считаются: в противном случае взаимный обмен именами между двумя объектами был бы невозможен.

**ТР-ПАК-12.** Объект, отсеянный отбором по полю «Найти», считается занимающим своё имя: он остаётся на месте, и целевое имя, совпавшее с его именем, должно быть отмечено конфликтом, а не привести к перезаписи.

**ТР-ПАК-13.** Объекты с конфликтом пропускаются при выполнении; остальные переименовываются.

**ТР-ПАК-14.** Если множество целевых имён пересекается с множеством исходных, выполнение производится в два прохода: сначала все объекты переименовываются во временные имена, затем — в целевые. Прямое выполнение затёрло бы объект, имя которого ещё требуется другому шагу.

**ТР-ПАК-15.** Шаги, не изменяющие имя, из проверки пересечения исключаются: их источник совпадает с целью по определению, и двухпроходный режим включался бы всегда.

**ТР-ПАК-16.** Отказ на отдельном шаге не прерывает операцию. По завершении отображается итог: число переименованных объектов из общего числа.

**ТР-ПАК-17.** Правило, не изменяющее ни одного имени, даёт пустой план операции; кнопка выполнения при этом недоступна.

### 5.5. Подсистема поиска

#### 5.5.1. Поиск по именам

**ТР-ПОИ-01.** Система выполняет рекурсивный поиск объектов в текущем каталоге и его подкаталогах по фрагменту имени. Команда — «Найти в папке…» (⌘F).

**ТР-ПОИ-02.** Поиск запускается по нажатию Enter, а не по мере ввода: на сетевых томах поиск при каждом нажатии клавиши недопустим по стоимости.

**ТР-ПОИ-03.** Поиск выполняет нечёткое сопоставление: учитываются совпадения подстроки, совпадение по началу имени и совпадение по разрозненным символам. Результаты внутри порции упорядочиваются по качеству совпадения.

**ТР-ПОИ-04.** Результаты выводятся по мере нахождения, порциями. Ранее показанные строки не переупорядочиваются: переупорядочивание всей выдачи при поступлении новой порции сделало бы невозможным переход к найденному объекту до завершения поиска.

**ТР-ПОИ-05.** Для каждого результата отображается путь относительно каталога, в котором выполнялся поиск.

**ТР-ПОИ-06.** Система отображает ход выполнения поиска в виде доли выполненного. Значение доли не убывает: оценка объёма работы может уточняться в сторону увеличения, а движущийся назад индикатор воспринимается как сбой.

**ТР-ПОИ-07.** Поиск прерывается пользователем; текущая выдача при этом сохраняется.

**ТР-ПОИ-08.** Переход к найденному объекту открывает содержащий его каталог и выделяет объект. Текст запроса при этом сохраняется, чтобы повторное нажатие Enter вернуло ту же выдачу.

**ТР-ПОИ-09.** Пустая выдача отличается от состояния «поиск не выполнялся»: в первом случае отображается сообщение об отсутствии результатов, во втором — обычный список файлов.

#### 5.5.2. Поиск внутри архивов

**ТР-ПОИ-10.** Поиск по именам просматривает содержимое архивов: имена записей внутри архива участвуют в сопоставлении наравне с именами файлов.

**ТР-ПОИ-11.** Оглавление архива читается напрямую из его структуры, без запуска внешних программ распаковки.

**ТР-ПОИ-12.** Архивы, превышающие пороговый размер, не просматриваются. Пороги:

| Размещение | Порог |
|---|---|
| Локальный диск | 500 МБ |
| Сетевой том | 50 МБ |

Различие порогов обусловлено тем, что архив на сетевом томе передаётся по сети целиком.

**ТР-ПОИ-13.** Число записей, читаемых из одного архива, ограничивается. Ограничение защищает память системы от намеренно или ошибочно сформированного архива с чрезмерным числом записей.

**ТР-ПОИ-14.** Число одновременно просматриваемых архивов ограничивается восемью. Дальнейшее увеличение не ускоряет поиск, а на сетевом томе исчерпывает пропускную способность канала.

**ТР-ПОИ-15.** Пропущенные по размеру архивы перечисляются пользователю с указанием их размера, и предоставляется возможность повторить поиск, включив их.

**ТР-ПОИ-16.** Двойной щелчок по записи внутри архива извлекает её во временный каталог и открывает приложением по умолчанию. Временный каталог создаётся отдельный на каждое извлечение, чтобы одноимённые записи из разных архивов не затирали друг друга.

#### 5.5.3. Поиск по содержимому

**ТР-ПОИ-17.** Система выполняет поиск по содержимому файлов. Режим включается командой «Искать в содержимом файлов» (⌥⌘F) и действует дополнительно к поиску по именам.

**ТР-ПОИ-18.** Содержимое читается из следующих категорий файлов:

| Категория | Форматы |
|---|---|
| Простой текст | `.txt`, `.md`, `.csv`, `.json`, `.xml`, `.log`, а также файлы исходного кода |
| Документы OOXML | `.docx`, `.xlsx`, `.pptx` |
| Переносимые документы | `.pdf` |

**ТР-ПОИ-19.** Из документов OOXML извлекаются только те части, которые содержат видимый пользователю текст. Служебные части (стили, темы оформления) не просматриваются: их содержимое дало бы совпадения по названиям шрифтов и иным техническим значениям, необъяснимые для пользователя.

**ТР-ПОИ-20.** Форматы `.doc` и `.xls` не поддерживаются.

**ТР-ПОИ-21.** Файлы, превышающие пороговый размер, не читаются. Пороги:

| Размещение | Порог |
|---|---|
| Локальный диск | 20 МБ |
| Сетевой том | 5 МБ |

**ТР-ПОИ-22.** Пороги поиска по содержимому задаются независимо от порогов просмотра архивов: чтение оглавления архива объёмом 500 МБ требует передачи килобайтов, тогда как чтение текста того же объёма требует передачи всех 500 МБ.

**ТР-ПОИ-23.** Число одновременно читаемых файлов ограничивается двенадцатью — независимо от ограничения на архивы, поскольку чтение файла существенно дешевле распаковки.

**ТР-ПОИ-24.** Пропущенные по размеру файлы перечисляются пользователю.

**ТР-ПОИ-25.** Файл, найденный одновременно по имени и по содержимому, отображается одной записью. Признак способа нахождения при этом обновляется на месте, без изменения позиции записи в списке.

**ТР-ПОИ-26.** Режим поиска по содержимому не сохраняется между запусками системы (см. ТР-СОСТ-02).

### 5.6. Подсистема работы с архивами

**ТР-АРХ-01.** Система создаёт архивы в форматах:

| Формат | Расширение | Пароль |
|---|---|---|
| ZIP | `.zip` | поддерживается |
| tar + gzip | `.tar.gz` | не поддерживается |
| tar + bzip2 | `.tar.bz2` | не поддерживается |
| tar + xz | `.tar.xz` | не поддерживается |

**ТР-АРХ-02.** Архивирование выполняется командой «Архивировать…». Пользователю предлагается указать имя архива, формат и, для ZIP, пароль.

**ТР-АРХ-03.** Имя архива по умолчанию формируется от имени объекта (при одном выбранном объекте) либо от имени содержащего каталога. Если предложенное имя занято, к нему добавляется порядковый номер.

**ТР-АРХ-04.** В архив помещаются относительные пути объектов. Все архивируемые объекты должны располагаться в одном каталоге.

**ТР-АРХ-05.** Система распаковывает архивы форматов ZIP, tar с любым из поддерживаемых сжатий, 7z и RAR.

**ТР-АРХ-06.** Распаковка выполняется по правилу: если архив содержит единственный объект верхнего уровня, он извлекается непосредственно в текущий каталог; иначе создаётся каталог с именем архива.

**ТР-АРХ-07.** Если архив зашифрован, система запрашивает пароль. Запрос представляется отдельным диалогом, а не сообщением об ошибке.

**ТР-АРХ-08.** Неверный пароль отличается от отсутствия пароля: пользователю сообщается о неверном пароле с возможностью повторного ввода.

**ТР-АРХ-09.** Зашифрованные архивы форматов 7z и RAR не распаковываются; пользователю сообщается об этом явно.

**ТР-АРХ-10.** Архивирование и распаковка отображают ход выполнения в долях от общего числа обрабатываемых записей.

**ТР-АРХ-11.** Операции архивирования и распаковки прерываются пользователем. Прерывание не считается ошибкой и не порождает сообщения.

**ТР-АРХ-12.** Прерывание операции не должно приводить к сообщению об ошибке выполнения внешней программы: проверка признака отмены выполняется до проверки кода завершения процесса.

### 5.7. Подсистема сетевых серверов

#### 5.7.1. Подключение

**ТР-СЕТ-01.** Система подключается к сетевым серверам по протоколам SMB и FTP посредством системного механизма монтирования.

**ТР-СЕТ-02.** Адрес сервера вводится в виде `smb://хост/ресурс`, `ftp://хост` либо `хост` без указания протокола.

**ТР-СЕТ-03.** При вводе адреса без указания протокола система определяет протокол опросом стандартных портов сервера. Определение выполняется с ограничением по времени.

**ТР-СЕТ-04.** Система отображает перечень доступных ресурсов (шар) сервера SMB, позволяя выбрать нужный.

**ТР-СЕТ-05.** Учётные данные для подключения выбираются в следующем порядке приоритета: явно введённые пользователем → сохранённые ранее → гостевой вход, если он разрешён для данной закладки.

**ТР-СЕТ-06.** Если ни один из вариантов не применим, выполняется попытка гостевого входа; при отказе запрашиваются учётные данные.

**ТР-СЕТ-07.** Результатом попытки подключения является одно из трёх состояний: подключено, требуются учётные данные, отказ с описанием причины.

**ТР-СЕТ-08.** Причина запроса учётных данных указывается пользователю явно и различает случаи:

| Причина | Формулировка для пользователя |
|---|---|
| Первое подключение | Сохранённых данных нет |
| Сохранённый пароль отклонён | Сервер не принял сохранённый пароль |
| Ресурс скрыт от гостя | Сервер не показывает ресурс без авторизации |

**ТР-СЕТ-09.** Учётные данные сохраняются по указанию пользователя. Ключом сохранения служит полный адрес ресурса, а не только имя хоста: на одном сервере разные ресурсы могут требовать разных учётных записей.

**ТР-СЕТ-10.** Система отображает признак выполняющегося подключения в строке соответствующего сервера боковой панели.

#### 5.7.2. Закладки серверов

**ТР-СЕТ-11.** Адреса подключённых серверов сохраняются в виде закладок и отображаются в секции «Сеть» боковой панели.

**ТР-СЕТ-12.** Закладка содержит адрес, отображаемое имя, признак разрешения гостевого входа и, при наличии, имя пользователя.

**ТР-СЕТ-13.** Закладка удаляется пользователем. Удаление закладки удаляет и сохранённые для неё учётные данные.

#### 5.7.3. Состояние томов

**ТР-СЕТ-14.** Система отображает состояние каждого сервера: подключён, не подключён, подключается.

**ТР-СЕТ-15.** Список подключённых томов не сохраняется между запусками: за время простоя системы том мог быть отключён. Вместо этого при запуске выполняется опрос фактически смонтированных томов средствами ОС, что позволяет отобразить в том числе тома, смонтированные из Finder.

**ТР-СЕТ-16.** Отключение тома выполняется по команде пользователя. Отказ ОС в размонтировании сообщается пользователю с текстом причины.

#### 5.7.4. Переподключение

**ТР-СЕТ-17.** После выхода рабочей станции из режима сна система проверяет отзывчивость смонтированных сетевых томов и переподключает те из них, которые перестали отвечать.

**ТР-СЕТ-18.** Неотвечающий том принудительно размонтируется в любом случае — в том числе когда повторное подключение заведомо невозможно. Оставленный в системе, такой том вызывает зависание при каждом обращении к нему до истечения системного таймаута.

**ТР-СЕТ-19.** Проверка отзывчивости тома выполняется с ограничением по времени; отсутствие ответа в течение установленного срока трактуется как потеря соединения.

### 5.8. Подсистема создания документов

**ТР-ДОК-01.** Система создаёт в текущем каталоге пустые документы следующих форматов:

| Формат | Расширение |
|---|---|
| Текстовый документ | `.txt` |
| Документ RTF | `.rtf` |
| Документ Word | `.docx` |
| Книга Excel | `.xlsx` |
| Презентация PowerPoint | `.pptx` |
| Документ Pages | `.pages` |
| Таблица Numbers | `.numbers` |
| Презентация Keynote | `.key` |

**ТР-ДОК-02.** Документ создаётся копированием заготовки либо записью подготовленного содержимого — без запуска приложения-редактора. Файл появляется в списке немедленно.

**ТР-ДОК-03.** Заготовка формата OOXML формируется программно и представляет собой корректный документ соответствующего формата.

**ТР-ДОК-04.** Файл нулевой длины вместо заготовки не допускается: редактор счёл бы такой документ повреждённым, причём выяснилось бы это только при открытии.

**ТР-ДОК-05.** Состав меню создания документов не зависит от набора установленных на рабочей станции приложений: все пункты доступны всегда. Заготовка остаётся корректной независимо от того, каким приложением она будет открыта, а меню, различающееся на разных рабочих станциях, затрудняет поддержку пользователей.

**ТР-ДОК-06.** Имя нового документа предлагается по умолчанию, при занятости имени добавляется порядковый номер. Созданный документ сразу переводится в режим переименования.

### 5.9. Подсистема свойств объектов

**ТР-СВО-01.** Система отображает свойства выбранного объекта по команде «Свойства» (⌘I).

**ТР-СВО-02.** Для одиночного объекта отображаются: имя, тип, размещение, дата создания, дата изменения, права доступа, размер.

**ТР-СВО-03.** Размещение отображается с сокращением домашнего каталога до символа `~`.

**ТР-СВО-04.** Для каталога размер не известен сразу и подсчитывается рекурсивно в фоне с отображением промежуточного результата.

**ТР-СВО-05.** Для группы выбранных объектов отображаются: число объектов, общее размещение (или указание на разные каталоги), общий тип (или указание на разные типы), суммарный размер.

**ТР-СВО-06.** Имя, даты и права для группы не отображаются: для группы эти сведения не имеют смысла.

**ТР-СВО-07.** Наличие каталога среди выбранных объектов делает набор разнородным по типу.

**ТР-СВО-08.** Свойства формируются как снимок состояния на момент открытия диалога, а не как ссылка на изменяющийся список: содержимое каталога может измениться, пока диалог открыт.

**ТР-СВО-09.** Команда «Свойства» доступна в том числе на томах только для чтения: операция не изменяет данных.

### 5.10. Подсистема отображения занятости томов

**ТР-ТОМ-01.** Система отображает в боковой панели для каждого смонтированного тома его общий объём, свободное и занятое место, а также графический индикатор заполнения.

**ТР-ТОМ-02.** Занятое место вычисляется вычитанием свободного из общего, а не запрашивается у ОС напрямую: на файловой системе APFS загрузочный том входит в контейнер с общим пулом пространства, и прямой запрос даёт значение, не соответствующее ожиданиям пользователя.

**ТР-ТОМ-03.** Тома, для которых сведения о занятости недостоверны, отображаются без индикатора заполнения. К таковым относятся тома FTP: системный мост, через который они монтируются, возвращает фиксированную заглушку вместо фактического состояния сервера.

**ТР-ТОМ-04.** Недостоверность сведений определяется по признаку файловой системы тома, а не по правдоподобности чисел: возвращаемые заглушкой значения внешне правдоподобны.

**ТР-ТОМ-05.** По умолчанию сведения считаются достоверными; недостоверность объявляется явно. Обратное умолчание привело бы к исчезновению индикаторов у всех томов при любом сбое системного запроса.

### 5.11. Подсистема команд и горячих клавиш

**ТР-КОМ-01.** Все команды системы описываются в едином реестре, служащем единственным источником сведений о заголовке, значке, сочетании клавиш и условиях доступности команды.

**ТР-КОМ-02.** Главное меню и контекстные меню строятся из реестра. Дублирование описаний команд не допускается.

**ТР-КОМ-03.** Сочетания клавиш команд не должны конфликтовать между собой. Отсутствие конфликтов подлежит автоматизированной проверке.

**ТР-КОМ-04.** Действие, вызванное из контекстного меню списка файлов, применяется к объекту, по которому выполнен щелчок, а не к текущему выделению. Данное поведение соответствует принятому в macOS: щелчок правой кнопкой по невыделенному объекту действует на этот объект.

**ТР-КОМ-05.** При вводе текста (переименование по месту, адресная строка, поля диалогов) команды, способные разрушить ввод, должны быть недоступны.

**ТР-КОМ-06.** Команды работы с буфером обмена (⌘C, ⌘X, ⌘V, ⌘A) не должны перехватывать сочетания клавиш у текстовых полей. Одно и то же сочетание должно работать и в списке файлов, и в поле ввода — как это принято в системе.

**ТР-КОМ-07.** Сочетания клавиш не назначаются кнопкам интерфейса: назначенное кнопке сочетание перестаёт работать при её недоступности и при нахождении фокуса вне кнопки.

**ТР-КОМ-08.** Клавиша быстрого просмотра (Пробел) не регистрируется как сочетание пункта меню: зарегистрированная, она перехватывалась бы глобально, и ввод пробела в именах файлов, адресной строке и поле поиска стал бы невозможен. Пункт меню при этом присутствует — для обнаружимости возможности.

**ТР-КОМ-09.** Пункты контекстного меню, соответствующие командам без собственного сочетания клавиш, но имеющие системное сочетание, должны отображать это сочетание: пункт без подписи создаёт впечатление, что клавиши не существует.

### 5.12. Подсистема обновления

**ТР-ОБН-01.** Система самостоятельно проверяет наличие новой версии, обращаясь к сервису публикации релизов.

**ТР-ОБН-02.** Проверка выполняется не чаще одного раза в сутки, а также по явному запросу пользователя.

**ТР-ОБН-03.** Сравнение версий выполняется покомпонентно как сравнение чисел. Строковое сравнение недопустимо: оно дало бы неверный результат для пары версий 1.10.0 и 1.9.0.

**ТР-ОБН-04.** Система отображает в заголовке окна индикатор состояния обновления со следующими состояниями:

| Состояние | Условие |
|---|---|
| Не проверялось | Обращение к сервису ещё не выполнялось |
| Проверяется | Запрос выполняется |
| Установлена последняя версия | Проверка выполнена, новее нет |
| Доступна версия N | Обнаружена новая версия |
| Загружается | Идёт загрузка, с указанием доли |
| Готово к перезапуску | Загруженная версия проверена и ждёт установки |
| Ошибка | С указанием причины |

**ТР-ОБН-05.** Состояние «не проверялось» отличается от состояния «установлена последняя версия»: утверждать второе, не обратившись к сервису, недопустимо.

**ТР-ОБН-06.** При обнаружении новой версии система показывает системное уведомление. Отказ пользователя в разрешении на уведомления не влияет на работу подсистемы: индикатор в заголовке окна отображается независимо от разрешений.

**ТР-ОБН-07.** В уведомлении и в описании обновления отображаются заметки к выпускам, вышедшим после установленной версии. Заметки к более ранним выпускам не отображаются.

**ТР-ОБН-08.** Загруженное обновление проверяется на целостность и корректность до замены установленной версии.

**ТР-ОБН-09.** Замена установленной версии выполняется по команде пользователя «Перезапустить», а не по завершении загрузки. Процедура замены отводит фиксированное время на завершение работы приложения; будучи запущенной по завершении загрузки, она отсчитывала бы это время не процессу, а раздумьям пользователя, и отложивший перезапуск не получил бы обновления вовсе.

**ТР-ОБН-10.** Процедура замены обеспечивает откат: прежняя версия сохраняется и восстанавливается, если новая не запустилась в течение установленного срока. Сохранённая прежняя версия удаляется самой новой версией после успешного запуска.

**ТР-ОБН-11.** Пути к файлам передаются процедуре замены аргументами, а не подстановкой в текст команды. Подстановка допускала бы выполнение произвольных команд при наличии в пути специальных символов интерпретатора, а процедура удаляет каталоги в системном каталоге приложений.

**ТР-ОБН-12.** Разбор ответа сервиса публикации выполняется по явно заданному соответствию полей. Автоматическое преобразование имён полей не применяется: оно не распознаёт аббревиатуры в именах, что привело бы к молчаливому отказу разбора и полному прекращению получения обновлений при внешне исправной системе.

**ТР-ОБН-13.** Загружаемое обновление не должно помечаться системой как объект неизвестного происхождения. Данное требование определяет ограничение: в описании приложения не должен объявляться признак, включающий такую пометку (см. п. 11.4).

### 5.13. Подсистема обучения

**ТР-ОБУ-01.** При первом запуске система предлагает обучающий тур по основным возможностям.

**ТР-ОБУ-02.** Тур состоит из последовательных шагов с отображением прогресса. Состав шагов:

| Шаг | Содержание |
|---|---|
| Приветствие | Назначение системы |
| Адресная строка | Ввод и редактирование пути |
| Дерево и избранное | Навигация по боковой панели |
| Сетевые серверы | Подключение к серверам |
| Обновления | Индикатор версии и получение обновлений |
| Завершение | Итог |

**ТР-ОБУ-03.** Каждый шаг, кроме первого и последнего, подсвечивает соответствующий элемент интерфейса.

**ТР-ОБУ-04.** Тур прерывается пользователем на любом шаге.

**ТР-ОБУ-05.** Факт прохождения либо прерывания тура сохраняется; повторно тур не предлагается.

**ТР-ОБУ-06.** Тур вызывается пользователем повторно из меню справки.

### 5.14. Подсистема интеграции с внешними средствами

**ТР-ИНТ-01.** Система открывает текущий каталог в системном терминале командой «Открыть в Терминале» (⇧⌘T).

**ТР-ИНТ-02.** Открытие каталога в терминале выполняется штатным механизмом открытия документа приложением, а не отправкой команды приложению. Первый способ не требует от пользователя разрешения на управление другими приложениями.

**ТР-ИНТ-03.** Система открывает текущий каталог в средстве разработки Claude Code, если оно установлено. При отсутствии средства команда недоступна.

**ТР-ИНТ-04.** Система открывает объект в Finder командой «Показать в Finder» (⇧⌘R).

**ТР-ИНТ-05.** Система вызывает системный механизм быстрого просмотра для выделенных объектов по клавише Пробел.

## 7. Требования к производительности

### 7.1. Загрузка содержимого каталога

**ТР-ПРЗ-01.** Загрузка содержимого каталога выполняется в три ступени:

| Ступень | Содержание | Приоритет |
|---|---|---|
| 1 | Отображение из кэша | Синхронно, до первой асинхронной операции |
| 2 | Чтение имён и типов объектов | Высокий |
| 3 | Чтение метаданных (размеры, даты) | Пониженный |

**ТР-ПРЗ-02.** Отображение из кэша выполняется синхронно, чтобы возврат в ранее посещённый каталог отрисовывался в том же цикле обновления интерфейса.

**ТР-ПРЗ-03.** При чтении имён тип объекта (файл или каталог) определяется из данных, возвращаемых операцией обхода каталога, без дополнительных обращений к диску по каждому объекту.

Обоснование: замер на каталоге, содержащем 510 подкаталогов, дал 4824 мс при определении типа отдельным обращением к диску против 0,7 мс при использовании данных обхода.

**ТР-ПРЗ-04.** В кэш записываются только полные записи, содержащие метаданные.

**ТР-ПРЗ-05.** Ключ кэша включает признак отображения скрытых файлов. Без этого переключение режима отображало бы список, соответствующий противоположному режиму.

**ТР-ПРЗ-06.** Операции копирования и перемещения объявляют недействительными кэш каталога-приёмника, а перемещение — также кэш родительских каталогов источников.

**ТР-ПРЗ-07.** Смена каталога отменяет выполняющуюся загрузку. Дополнительно после каждой асинхронной операции проверяется, что текущий каталог не изменился: отмена носит кооперативный характер и не прерывает уже начатую операцию.

### 7.2. Отображение списка

**ТР-ПРЗ-08.** Компоновка строки списка выполняется способом, обеспечивающим приемлемую скорость прокрутки.

Обоснование: замер показал 1,4 мс на строку при использовании системы автоматической компоновки, что даёт 56 мс на экран при прокрутке — недопустимую задержку.

**ТР-ПРЗ-09.** Значки объектов кэшируются. Обращение к системному механизму получения значка для каждой строки недопустимо.

Обоснование: замер показал 3,1 мс на строку, что даёт 125 мс на экран.

**ТР-ПРЗ-10.** Полное обновление списка при изменениях не применяется, если состав и состояние объектов не изменились: полное обновление сбрасывает позицию прокрутки.

### 7.3. Работа с сетевыми томами

**ТР-ПРЗ-11.** Все операции, обращающиеся к сетевым томам, выполняются асинхронно и допускают прерывание.

**ТР-ПРЗ-12.** Оглавление архива читается напрямую из структуры архива, без запуска внешней программы.

Обоснование: замер дал 0,03 мс против 2,5 мс на запуск процесса; по сети разница возрастает многократно.

**ТР-ПРЗ-13.** Пороговые значения объёмов, применяемые при поиске, для сетевых томов устанавливаются строже, чем для локальных дисков (см. ТР-ПОИ-12, ТР-ПОИ-21).

**ТР-ПРЗ-14.** Число одновременных обращений к сетевому тому ограничивается (см. ТР-ПОИ-14, ТР-ПОИ-23).

### 7.4. Общие показатели

**ТР-ПРЗ-15.** Интерфейс системы должен оставаться отзывчивым при выполнении любой операции. Блокирование интерфейса на время выполнения операции не допускается.

**ТР-ПРЗ-16.** Показатели, подлежащие проверке при приёмке:

| Показатель | Требование |
|---|---|
| Запуск системы до отображения окна | не более 1 с |
| Отображение каталога из кэша | в том же цикле отрисовки |
| Отображение имён объектов локального каталога до 10 000 объектов | не более 300 мс |
| Прокрутка списка | без видимых пропусков кадров |
| Переключение вкладок | не более 100 мс |

## 8. Требования к надёжности и обработке ошибок

### 8.1. Общие принципы

**ТР-НАД-01.** Система не должна завершаться аварийно при любых входных данных и любом состоянии файловой системы.

**ТР-НАД-02.** Молчаливый отказ операции не допускается: результат каждой операции либо виден пользователю, либо сообщается ему.

**ТР-НАД-03.** Прерывание операции пользователем не является ошибкой и не сопровождается сообщением.

### 8.2. Перечень обрабатываемых ситуаций

**ТР-НАД-04.** Система обрабатывает следующие нештатные ситуации:

| Ситуация | Реакция системы |
|---|---|
| Отсутствие прав доступа к каталогу | Сообщение с указанием, где выдать полный доступ к диску |
| Каталог удалён во время просмотра | Переход к ближайшему существующему родителю, сообщение |
| Объект исчез до выполнения операции | Пропуск объекта без прерывания операции |
| Недостаточно места на диске | Сообщение с указанием числа обработанных объектов |
| Объект занят другим процессом | Сообщение с именем объекта |
| Целевое имя занято | Диалог разрешения конфликта |
| Сетевой том перестал отвечать | Принудительное размонтирование и попытка переподключения |
| Отказ авторизации на сервере | Запрос учётных данных с указанием причины |
| Архив зашифрован | Запрос пароля |
| Неверный пароль архива | Повторный запрос с указанием причины |
| Зашифрованный 7z или RAR | Сообщение о неподдерживаемом случае |
| Отказ загрузки обновления | Сообщение с возможностью повтора |
| Новая версия не запустилась | Автоматический откат к прежней версии |
| Отказ внешней программы | Сообщение с текстом отказа программы |

### 8.3. Каналы сообщений

**ТР-НАД-05.** Сообщения об ошибках разделяются на два независимых канала:

| Канал | Содержание |
|---|---|
| Файловые операции | Операции с файлами, архивы |
| Интеграция | Терминал, внешние средства разработки |

**ТР-НАД-06.** Ситуации, требующие ввода данных пользователем (запрос пароля к архиву, запрос учётных данных), не преобразуются в текстовое сообщение об ошибке, а порождают соответствующий диалог.

### 8.4. Целостность операций

**ТР-НАД-07.** Групповая операция не прерывается при отказе на отдельном объекте. По завершении отображается сводный итог.

**ТР-НАД-08.** Пакетное переименование, при котором целевые имена пересекаются с исходными, выполняется в два прохода через временные имена (см. ТР-ПАК-14).

**ТР-НАД-09.** Замена установленной версии обеспечивает откат к прежней версии (см. ТР-ОБН-10).

## 9. Требования к безопасности

### 9.1. Модель угроз

**ТР-БЕЗ-01.** Система работает от имени пользователя ОС и наследует его права. Повышение привилегий не выполняется.

**ТР-БЕЗ-02.** Защищаемым активом являются учётные данные для доступа к сетевым серверам.

**ТР-БЕЗ-03.** Рассматриваемая угроза — получение учётных данных при копировании файлов конфигурации системы на другую рабочую станцию либо доступе к ним от имени иного пользователя той же станции.

### 9.2. Хранение учётных данных

**ТР-БЕЗ-04.** Учётные данные хранятся в зашифрованном файле в каталоге поддержки приложения.

**ТР-БЕЗ-05.** Ключ шифрования формируется из сведений, уникальных для рабочей станции и учётной записи пользователя ОС: идентификатора оборудования и идентификатора пользователя.

**ТР-БЕЗ-06.** Домашний каталог пользователя в формирование ключа не входит: его переименование не должно обесценивать сохранённые данные.

**ТР-БЕЗ-07.** Ключ шифрования должен быть воспроизводим между запусками. При недоступности источника идентификатора оборудования применяется постоянное значение-заглушка; случайное значение недопустимо, поскольку сделало бы сохранённые данные нечитаемыми уже при следующем запуске.

**ТР-БЕЗ-08.** Граница защиты объявляется явно: файл не расшифровывается на другой рабочей станции и другим пользователем ОС, но расшифровывается любым процессом, запущенным от имени владельца.

**ТР-БЕЗ-09.** Использование системного хранилища паролей (Связки ключей) не применяется. Обоснование: при подписи приложения без сертификата разработчика система расценивает каждую сборку как иную программу и сопровождает чтение пароля диалогом подтверждения. Устранить диалог, оставаясь в системном хранилище, невозможно.

**ТР-БЕЗ-10.** Учётные данные, сохранённые предыдущими версиями системы в системном хранилище, переносятся в новое хранилище автоматически при первом обращении.

**ТР-БЕЗ-11.** Проверка наличия сохранённых учётных данных выполняется без их чтения. Обоснование: чтение данных пароля влечёт системный диалог подтверждения, тогда как факт наличия записи устанавливается без него.

### 9.3. Прочие требования

**ТР-БЕЗ-12.** Пароли не отображаются в открытом виде и не записываются в диагностические сообщения.

**ТР-БЕЗ-13.** Пути, передаваемые внешним программам и сценариям, передаются аргументами, а не подстановкой в текст команды (см. ТР-ОБН-11).

**ТР-БЕЗ-14.** Команда, передаваемая терминалу, экранируется дважды: для интерпретатора команд и для механизма межпроцессного взаимодействия.

**ТР-БЕЗ-15.** Система работает без изоляции процесса (песочницы). Для доступа к пользовательским каталогам требуется однократная выдача полного доступа к диску в системных настройках. Данное решение обусловлено назначением системы: файловый менеджер, ограниченный песочницей, не способен отобразить произвольный каталог файловой системы.

## 10. Архитектурные требования

### 10.1. Технологический стек

**ТР-АРХ-01.** Язык реализации — Swift версии 6 с включённой проверкой безопасности параллельного доступа.

**ТР-АРХ-02.** Интерфейс реализуется декларативным UI-фреймворком платформы с точечным применением императивного фреймворка там, где декларативные средства не обеспечивают требуемых характеристик (список файлов, инструменты редактирования по месту, контекстные меню).

**ТР-АРХ-03.** Система сборки — штатный менеджер пакетов Swift. Использование файла проекта интегрированной среды разработки не предусматривается.

**ТР-АРХ-04.** Минимальная поддерживаемая версия ОС — macOS 15.

### 10.2. Разделение ядра и интерфейса

**ТР-АРХ-05.** Граница между ядром и интерфейсом проводится по признаку наличия типов, выполняющих отрисовку, а не по признаку принадлежности к тому или иному фреймворку. Обращение ядра к системным сервисам платформы допустимо.

**ТР-АРХ-06.** Понятия, требующие представления и в ядре, и в интерфейсе (сочетания клавиш, значки), описываются в ядре собственными типами, не зависящими от UI-фреймворков. Преобразование в типы фреймворков выполняется в отдельном модуле интерфейса.

**ТР-АРХ-07.** Значок команды описывается в ядре именем системного символа в виде строки. Построение изображения выполняется интерфейсом.

**ТР-АРХ-08.** Решение о том, является ли строка именем системного символа, принимается интерфейсом. Ядро хранит строку без интерпретации.

### 10.3. Обратный канал взаимодействия

**ТР-АРХ-09.** Команда, для выполнения которой требуется визуальное представление (редактор по месту, модальный диалог), выставляет в состоянии приложения признак запроса. Интерфейс исполняет запрос и сбрасывает признак.

**ТР-АРХ-10.** Данный механизм применяется для: переименования по месту, пакетного переименования, архивирования, редактирования пути, отображения свойств, быстрого просмотра, запроса пароля, поиска, раскрытия сведений о версии.

**ТР-АРХ-11.** Альтернатива — разделение реестра команд на выполнимые в ядре и требующие интерфейса — отвергается: она разрушила бы единственность источника сведений о командах (ТР-КОМ-01).

### 10.4. Границы с операционной системой

**ТР-АРХ-12.** Каждая граница взаимодействия с ОС описывается протоколом, допускающим подмену реализации. Перечень границ:

| Граница | Назначение |
|---|---|
| Монтирование томов | Подключение сетевых ресурсов |
| Хранение учётных данных | Сохранение и чтение паролей |
| Перечисление ресурсов сервера | Получение списка шар |
| Запуск терминала | Открытие каталога в терминале |
| Завершение приложения | Закрытие при обновлении |
| Получение сведений о релизах | Обращение к сервису публикации |
| Установка обновления | Замена бандла приложения |
| Буфер обмена | Обмен объектами с другими приложениями |
| Слежение за каталогом | Уведомление об изменениях |
| Извлечение текста | Чтение содержимого файлов при поиске |
| Показ уведомлений | Системные уведомления |
| Опрос портов | Определение протокола сервера |
| Распаковка архивов | Извлечение содержимого |
| Идентификация машины | Формирование ключа шифрования |
| Чтение занятости томов | Сведения о свободном месте |

**ТР-АРХ-13.** Каждая новая граница с ОС вводится по тому же принципу.

**ТР-АРХ-14.** Обоснование требования: без подмены реализации проверка логики системы требовала бы наличия сети, настроенных серверов, доступа к внешним сервисам и изменяла бы состояние рабочей станции, на которой выполняется проверка.

### 10.5. Модель состояния

**ТР-АРХ-15.** Поток данных однонаправленный: действие пользователя → метод модели → асинхронная работа ядра → изменение наблюдаемых свойств → обновление интерфейса.

**ТР-АРХ-16.** Состояние вкладки включает модель просмотра каталога, та — состояние панели и кэш. Независимость выделения, истории и кэша между вкладками обеспечивается этим разделением.

**ТР-АРХ-17.** Доступ к модели активной вкладки осуществляется через единое вычисляемое свойство состояния приложения. Обращение к активной вкладке по месту в каждом потребителе не допускается.

**ТР-АРХ-18.** Настройки, общие для всех вкладок (отображение скрытых файлов), хранятся в единственном месте. Дублирование хранения привело бы к расхождению значений.

**ТР-АРХ-19.** Сохранение сеанса инициируется моделью просмотра каталога при смене каталога, а не вызовом из интерфейса. Обоснование: каталог меняется внутри модели, минуя модель вкладок, и расчёт на то, что каждое место навигации вызовет сохранение, приводит к потере последнего каталога.

**ТР-АРХ-20.** Сохранение выполняется немедленно при смене каталога, а не при следующей отрисовке: завершение работы системы между сменой каталога и отрисовкой привело бы к потере пути.

### 10.6. Защита от повторного входа и гонок

**ТР-АРХ-21.** Синхронизация выделения между моделью и списком должна исключать обратную запись: программная установка выделения порождает уведомление, которое переписало бы модель отображённым состоянием.

**ТР-АРХ-22.** Начало редактирования по месту должно исключать повторный вход: повторная передача фокуса редактору сбрасывает позицию курсора во время ввода.

**ТР-АРХ-23.** Отмена редактирования должна исключать повторную обработку: клавиша Esc порождает то же уведомление о завершении редактирования, что и подтверждение.

**ТР-АРХ-24.** Привязки, передаваемые в объект-координатор списка, должны обновляться при каждом обновлении представления: привязка, полученная при первом построении, ведёт к экземпляру, вышедшему из употребления.

### 10.7. Ресурсы приложения

**ТР-АРХ-25.** Ресурсный каталог модуля не используется. Заготовки документов формируются программно.

Обоснование: ресурсный пакет, не попавший в собранное приложение, приводит к аварийному завершению процесса при обращении к нему.

## 11. Требования к сборке, поставке и обновлению

### 11.1. Сборка

**ТР-СБ-01.** Система собирается штатными средствами менеджера пакетов Swift без дополнительных инструментов.

**ТР-СБ-02.** Предусматриваются сценарии сборки: сборка приложения (`build-app.sh`), сборка образа для распространения (`make-dmg.sh`), выпуск релиза (`release.sh`).

**ТР-СБ-03.** Сценарий сборки приложения завершает выполняющийся экземпляр системы и заменяет установленную копию. Данное поведение должно быть задокументировано: оно является побочным эффектом, влияющим на установленную у разработчика копию.

### 11.2. Выпуск релиза

**ТР-СБ-04.** Выпуск релиза выполняется единственной командой с указанием номера версии. Команда самостоятельно выполняет: повышение номера версии в описании приложения, фиксацию изменения, установку метки версии, отправку изменений в удалённый репозиторий, сборку подписанного приложения, публикацию релиза с архивом.

**ТР-СБ-05.** Заметки к выпуску формируются из сообщений фиксаций, выполненных после предыдущей метки версии.

**ТР-СБ-06.** Сценарий выпуска отказывает в работе при следующих условиях:

| Условие | Обоснование |
|---|---|
| Текущая ветвь не является основной | Релиз из побочной ветви содержал бы незавершённую работу |
| Имеются незафиксированные изменения | Содержимое релиза не соответствовало бы содержимому репозитория |
| Указанная версия не выше текущей | Релиз с меньшим номером версии не был бы получен ни одним пользователем, а отозвать опубликованный релиз невозможно |

**ТР-СБ-07.** Нумерация версий: увеличение третьего компонента — исправления, второго — новые возможности, первого — существенная переработка. Номер версии изменяется только в сторону увеличения.

### 11.3. Подпись приложения

**ТР-СБ-08.** Приложение подписывается без сертификата разработчика (ad-hoc).

**ТР-СБ-09.** Параметры подписи в сценарии выпуска релиза должны дословно совпадать с параметрами подписи в сценарии сборки — идентификатор подписи и набор разрешений.

Обоснование: система разграничения доступа macOS и системное хранилище паролей связывают выданные разрешения и сохранённые данные с идентичностью подписи. Расхождение параметров привело бы к повторному запросу всех разрешений у пользователей и утрате доступа к сохранённым паролям серверов.

### 11.4. Ограничения, связанные с обновлением

**ТР-СБ-10.** В описании приложения не должен объявляться признак пометки загружаемых файлов как объектов неизвестного происхождения.

Обоснование: указанную пометку устанавливает не операционная система, а загружающая программа — та, которая объявила соответствующий признак в своём описании. При отсутствии признака загруженное системой обновление пометки не получает, проверка подписи не выполняется, и подписи без сертификата разработчика оказывается достаточно для установки. Объявление признака полностью нарушит работу подсистемы обновления, причём связь между причиной и следствием неочевидна, и поиск неисправности будет вестись в подсистеме загрузки.

### 11.5. Распространение

**ТР-СБ-11.** Система распространяется в виде архива приложения, публикуемого в разделе релизов репозитория.

**ТР-СБ-12.** Первичная установка выполняется пользователем: распаковка архива и перемещение приложения в системный каталог приложений. Последующие обновления выполняются системой самостоятельно.

**ТР-СБ-13.** Выпуск релизов выполняется владельцем продукта. Публикация релиза видна всем пользователям и инициирует у них обновление, поэтому момент публикации определяется владельцем.

## 12. Требования к тестированию

### 12.1. Общие требования

**ТР-ТЕСТ-01.** Автоматизированными проверками покрывается модуль ядра. Автоматизированные проверки пользовательского интерфейса не разрабатываются; вместо них для каждой возможности составляется перечень проверок, выполняемых вручную.

**ТР-ТЕСТ-02.** Обоснование отказа от автоматизированных проверок интерфейса: их стоимость сопровождения непропорциональна выявляемым дефектам, а требование к ядру не содержать типов отрисовки (ТР-АРХ-04) обеспечивает покрытие всей логики системы проверками ядра.

**ТР-ТЕСТ-03.** Применяется штатный фреймворк тестирования Swift.

### 12.2. Требования к оформлению проверок

**ТР-ТЕСТ-04.** Наименование набора проверок — описание на русском языке; идентификатор набора — на английском, вида `<Предмет>Tests`.

**ТР-ТЕСТ-05.** Наименование проверки — фраза на русском языке, описывающая проверяемое утверждение.

**ТР-ТЕСТ-06.** Наименование проверки, фиксирующей неочевидное поведение, должно содержать противопоставление отвергнутому варианту: «перемещает файл в Корзину, **а не** удаляет безвозвратно», «ключом служит полный адрес, **а не только** имя хоста».

**ТР-ТЕСТ-07.** Отбор проверок по имени выполняется только по английским идентификаторам. Отбор по русскому наименованию не выполняет ни одной проверки и при этом завершается успешно, что создаёт видимость успешного прогона.

### 12.3. Изоляция проверок

**ТР-ТЕСТ-08.** Проверки не должны зависеть от состояния рабочей станции, на которой выполняются, и не должны его изменять.

**ТР-ТЕСТ-09.** Хранилище пользовательских настроек изолируется созданием отдельного пространства имён на каждый набор проверок.

**ТР-ТЕСТ-10.** Файловые операции выполняются во временных каталогах, удаляемых по завершении проверки.

**ТР-ТЕСТ-11.** Обращение к системному хранилищу паролей выполняется только при явном включении соответствующим параметром окружения.

**ТР-ТЕСТ-12.** Обращения к сети, к сервису публикации релизов и к внешним программам заменяются подставными реализациями протоколов (см. ТР-АРХ-12).

**ТР-ТЕСТ-13.** Подставные реализации, где это требуется для проверки, ведут подсчёт обращений: в частности, хранилище учётных данных подсчитывает раздельно обращения на чтение и на проверку наличия — для контроля требования ТР-БЕЗ-11.

### 12.4. Обязательный состав проверок

**ТР-ТЕСТ-14.** Для каждой подсистемы разрабатываются проверки, охватывающие:

| Подсистема | Обязательные проверки |
|---|---|
| Загрузка каталога | Чтение имён, определение типа, скрытые файлы, сортировка, кэш и его недействительность |
| Файловые операции | Копирование, перемещение, переименование, перемещение в Корзину, конфликты имён |
| Пакетное переименование | Все компоненты правила, порядок применения, отбор по полю «Найти», все виды конфликтов, двухпроходное выполнение, взаимный обмен именами |
| Поиск | Сопоставление имён, нечёткое сопоставление, чтение оглавления архива, пороги размеров, отсутствие чтения содержимого при выключенном режиме |
| Архивы | Создание всех форматов, распаковка, пароли, различение отсутствия и неверности пароля, подбор свободного имени |
| Сетевые серверы | Приоритет выбора учётных данных, все виды исхода подключения, ключ хранения по полному адресу, разбор перечня ресурсов, переподключение неотвечающих томов |
| Учётные данные | Шифрование и расшифровка, воспроизводимость ключа, перенос из системного хранилища, раздельный подсчёт чтения и проверки наличия |
| Вкладки | Независимость состояния, отложенная загрузка, все ветви изменения активной вкладки, закрепление, сохранение и восстановление сеанса |
| Команды | Отсутствие конфликтов сочетаний клавиш, полнота реестра, условия доступности |
| Обновление | Сравнение версий покомпонентно, разбор ответа сервиса, все переходы состояний, порядок «подготовка — завершение работы — замена», отбор заметок по версии |
| Свойства | Одиночный объект и группа, определение общего размещения и типа, подсчёт размера каталога |
| Занятость томов | Вычисление занятого места, признак недостоверности, умолчание достоверности |

**ТР-ТЕСТ-15.** Проверка отсутствия конфликтов сочетаний клавиш является обязательной и выполняется по всему реестру команд.

### 12.5. Особенности среды выполнения проверок

**ТР-ТЕСТ-16.** При сравнении путей следует учитывать, что механизм обхода каталога приводит пути к каноническому виду, тогда как путь, составленный присоединением компонента, канонизации не проходит. Сравнение и формирование выделения в проверках выполняются от путей, полученных от модели.

### 12.6. Показатель покрытия

**ТР-ТЕСТ-17.** Ориентировочный объём — не менее 700 проверок при полном составе функциональности, определённом настоящим документом.

## 13. Этапы разработки

Разработка ведётся итерационно. Каждый этап завершается работоспособной версией системы.

### 13.1. Порядок выполнения работ

**ТР-ПРОЦ-01.** Каждой доработке предшествует разработка спецификации. Спецификация размещается в `docs/superpowers/specs/` под именем вида `ГГГГ-ММ-ДД-<тема>-design.md`.

**ТР-ПРОЦ-02.** Структура спецификации: цель → архитектура (с указанием конкретных файлов) → поток данных → тесты → перечень ручных проверок → вне рамок.

**ТР-ПРОЦ-03.** Раздел «Тесты» спецификации содержит перечень конкретных проверок и служит заданием на разработку файла проверок.

**ТР-ПРОЦ-04.** Раздел «Вне рамок» перечисляет отвергнутые варианты с указанием причины отклонения.

**ТР-ПРОЦ-05.** Последовательность выполнения доработки: спецификация → сервис в ядре → интеграция в модель → интерфейс. Каждый шаг фиксируется отдельно.

### 13.2. Состав этапов

| Этап | Содержание | Требования |
|---|---|---|
| **1. Базовая функциональность** | Одно окно, дерево каталогов, адресная строка, список файлов, навигация, основные файловые операции, перетаскивание, слежение за каталогом, скрытые файлы | 5.1, 5.3, 6, 7.1, 7.2 |
| **2. Реестр команд** | Единый реестр, построение главного и контекстного меню, разрешение конфликтов сочетаний клавиш | 5.11 |
| **3. Архивы** | Создание и распаковка, форматы, пароли, ход выполнения | 5.6 |
| **4. Сетевые серверы** | Подключение, определение протокола, перечень ресурсов, учётные данные, закладки | 5.7 |
| **5. Обновление** | Проверка версии, загрузка, замена, откат, уведомления, заметки к выпускам | 5.12, 11 |
| **6. Вкладки** | Множественные вкладки, независимость состояния, сохранение сеанса, закрепление | 5.2 |

| **11. Пакетное переименование** | Правила, предварительный просмотр, конфликты, двухпроходное выполнение | 5.4 |

### 13.3. Требования к фиксации изменений

**ТР-ПРОЦ-06.** Язык сообщений о фиксации изменений — русский. Префиксы вида `feat:`, `fix:` не применяются.

**ТР-ПРОЦ-07.** Заголовок сообщения — именная группа, при необходимости с указанием области через двоеточие.

**ТР-ПРОЦ-08.** Тело сообщения содержит связное изложение: что сделано, по какой причине избран данный способ, какие варианты отвергнуты, какие ограничения сохраняются. Изложение ведётся текстом, а не перечнем.

**ТР-ПРОЦ-09.** Объём сообщения соразмерен нетривиальности изменения: незначительные изменения фиксируются без тела сообщения.

**ТР-ПРОЦ-10.** Одному смысловому изменению соответствует одна фиксация.

### 13.4. Требования к комментариям в коде

**ТР-ПРОЦ-11.** Комментарии объясняют причину принятого решения, а не содержание кода. Комментарии, пересказывающие код, не допускаются.

**ТР-ПРОЦ-12.** Типовая форма комментария содержит обоснование и явное указание на отвергнутый вариант («иначе …», «а не …»).

**ТР-ПРОЦ-13.** Результаты замеров производительности приводятся в комментариях числами: они являются обоснованием принятого архитектурного решения.

**ТР-ПРОЦ-14.** Язык кода, комментариев, проверок, спецификаций и сообщений о фиксации — русский.

## 14. Критерии приёмки

### 14.1. Функциональные критерии

**ТР-ПРИЁМ-01.** Реализованы все требования разделов 5 и 6, отмеченные как обязательные.

**ТР-ПРИЁМ-02.** Выполнены проверки перечня, приведённого в п. 12.4.

## 15. Вне рамок проекта

Настоящий раздел перечисляет возможности, сознательно не включённые в объём работ, с указанием причины.

### 15.1. Не реализуется в принципе

| Возможность | Причина отклонения |
|---|---|
| **Безвозвратное удаление** | Противоречит требованию сохранности данных (ТР-СОХР-01). Корзина обеспечивает восстановление ошибочно удалённого |
| **Работа в песочнице** | Несовместима с назначением системы: изолированное приложение не отображает произвольные каталоги файловой системы |
| **Сбор телеметрии и отчётов об ошибках** | Противоречит требованию ТР-ЗАЩ-03. Круг пользователей узок, обратная связь поступает напрямую |
| **Автоматизированные проверки интерфейса** | Стоимость сопровождения непропорциональна выявляемым дефектам (ТР-ТЕСТ-02) |
| **Собственный переключатель темы оформления** | Системная настройка достаточна; собственный переключатель создаёт расхождение с остальными приложениями |
| **Проверка наличия установленных офисных приложений** | Меню, различающееся на разных рабочих станциях, затрудняет поддержку пользователей (ТР-ДОК-05) |
| **Хранение паролей в системном хранилище** | Влечёт системный диалог подтверждения при каждом чтении из-за подписи без сертификата разработчика (ТР-БЕЗ-09) |
| **Отдельный признак режима поля «Найти» в пакетном переименовании** | Два поведения одного поля породили бы вопрос о текущем режиме при каждом открытии диалога (ТР-ПАК-05) |
| **Сохранение режима поиска по содержимому между запусками** | Включённый и забытый режим даёт необъяснимо медленный поиск при следующем запуске (ТР-ПОИ-26) |
| **Сохранение списка смонтированных томов** | Том мог быть отключён за время простоя; опрос фактического состояния достовернее (ТР-СЕТ-15) |
| **Поддержка форматов `.doc` и `.xls` при поиске по содержимому** | Устаревшие двоичные форматы; трудоёмкость разбора несоразмерна распространённости |
| **Извлечение отдельной записи из архива средствами внешней программы** | Внешняя программа при запуске из процесса приложения не находит записи с кириллическими именами; в системе, где файлы именуются по-русски, такое поведение непригодно |

### 15.2. Возможные направления развития

Перечисленное не входит в объём настоящего задания, но не отвергается:

- двухпанельный режим отображения;
- альтернативные представления списка (значки, плитка);
- панель предварительного просмотра;
- метки и цветовые отметки объектов;
- фильтрация списка по типу объекта;
- настройка плотности отображения списка;
- сравнение содержимого каталогов;
- подключение к серверам по протоколам WebDAV и SFTP;
- распространение через образ диска с нотаризацией Apple.
